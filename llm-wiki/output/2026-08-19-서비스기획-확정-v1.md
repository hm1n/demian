# 서비스 기획 확정 (v1)

## 문서 목적

wiki/사전-인터뷰-4건-종합.md에 남아 있던 "확인 필요" 항목들을 사용자와 논의해 결정한 내용을 정리한다. 이 문서는 서비스 기획과 MVP 핵심 기능의 확정본이다.

## 문제 정의 (확정)

원래 문제 정의는 raw/2026-08-19-서비스기획안.md 기준 "시간이 지나면 자신의 코드에서 어떤 경험이 설명할 가치가 있는지 선별하고 정리해 설명하기 어렵다"이다. 인터뷰 결과로 이 문제는 다음 세 가지로 구체화된다.

1. 경험 선별의 어려움은 후보를 못 찾는 것이 아니라 우선순위를 매길 기준이 없다는 것이다.
2. 발견한 경험을 조리 있게 핵심만 전달하는 표현력 문제가 별도로 존재한다.
3. AI가 작성한 코드나 바이브 코딩 결과물에 대해 자신의 경험이라 말하기 어려워하는 소유감 문제가 있다.

근거: wiki/사전-인터뷰-4건-종합.md의 "제품 가설과 다른 점" 절.

## 핵심 가치 (유지)

`Repository → 경험 선별 → 근거 확인 → AI Interview → 경험 구체화`

AI는 이력서나 코드 설명을 대신 작성하지 않는다. 항상 실제 Repository의 커밋과 파일을 근거로 제시하고, Repository만으로 확인할 수 없는 사실은 명확히 구분해 보여준다.

## 결정 사항

### 1. AI 코드 소유감 문제 — 별도 기능 없이 포함

raw/2026-08-19-ai코드-소유감-재해석-session-log.md의 논의대로, 별도 기능을 추가하지 않는다. 기존 핵심 루프(코드 근거 질문 → 사용자 의도 설명 → 꼬리 질문)가 사람이 짠 코드든 AI가 짠 코드든 동일하게 적용된다. 바이브 코딩 결과물일수록 사용자가 의도를 되짚어야 할 필요가 크므로, 지금 설계 그대로 이 문제를 다룬다.

이 결정에 따라 "AI 비중이 높은 커밋을 경험 후보 선별 우선순위로 삼을지"는 별도로 채택하지 않는다. 소유감 문제는 선별 단계가 아니라 인터뷰 단계에서 자연스럽게 드러나는 것으로 본다.

### 2. 경험 후보 선별 우선순위 기준 — 확정

인터뷰이 2, 4가 지적한 "우선순위 기준 자체가 없다"는 문제에 대한 답으로, 다음 두 기준을 경험 후보 생성 로직에 반영한다.

- 코드 변경 규모/복잡도: 커밋당 diff 라인 수, 변경 파일 수, 여러 커밋에 걸친 연속 작업 여부 등 Repository에서 직접 계산 가능한 지표.
- 기술적 의사결정 흔적: 라이브러리 교체, 아키텍처 패턴 도입, 리팩토링처럼 "선택"이 드러나는 커밋 메시지/코드 패턴.

두 기준 모두 Repository 데이터만으로 계산 가능해야 한다. 근거 없이 추정하는 지표(예: 실제 성능 개선 수치, AI 작성 비중)는 선별 기준에서 제외하고, 대신 인터뷰 단계에서 "Repository만으로 확인할 수 없는 사실"로 구분해 보여준다.

### 3. Repository 근거 vs 사용자 실제 습관 — 단독 유지 + 확장 가능한 구조

인터뷰 결과 사용자는 노션 등 자체 기록을 Repository보다 더 신뢰한다. MVP는 원안대로 Repository 근거만 사용하지만, 이후 사용자가 보조 텍스트(노션 메모 등)를 근거로 추가할 수 있도록 확장 가능하게 설계한다.

구현 방향: 경험 후보와 근거 데이터 모델에 근거 출처 필드를 두어 현재는 `repository` 값만 사용하고, 이후 `user_note` 같은 값을 추가할 수 있게 한다. 근거 표시 UI도 출처 종류별로 구분해 보여줄 수 있는 구조로 설계하되, MVP 구현 범위에는 보조 텍스트 입력 기능 자체를 넣지 않는다.

### 4. 표현력 문제 — 인터뷰 설계에 반영하지 않음

인터뷰이 3이 지적한 "장황하게 설명하게 됨" 문제는 이번 인터뷰 설계에 반영하지 않는다. 코드 근거 질문 + 꼬리 질문이라는 기존 원칙만으로 충분히 커버 가능하다고 판단한다.

## MVP 핵심 기능 (확정)

raw/2026-08-19-서비스기획안.md MVP 목록에 위 결정 사항을 반영한 최종 범위는 다음과 같다.

- GitHub Repository 입력
- Repository 데이터 조회 및 기본 분석
- 개발 경험 후보 최대 3개 생성 (선별 기준: 코드 변경 규모/복잡도, 기술적 의사결정 흔적)
- 경험 후보별 Repository 근거 표시 (근거 출처 필드 포함, 확장 가능한 구조)
- 경험 선택
- 실제 코드 기반 AI 질문
- 사용자 답변
- 실시간 AI Streaming 응답
- 꼬리 질문
- Loading / Empty / Error 상태

프론트엔드 기술 챌린지와 기술 스택은 raw/2026-08-19-서비스기획안.md 원안을 그대로 따른다.
