# 강사 피드백 기반 한계점 대응 결정 (v1)

## 문서 목적

wiki/2026-08-19-강사피드백-기반-한계점-분석.md에서 정리한 5개 한계점 항목에 대해 사용자와 논의해 결정한 대응 방향을 정리한다.

## 결정 사항

### 1, 3. 의도 없이 위임한 사용자, 최소 숙련도 이하 사용자 — 이번 5일 작업 범위에서 제외

두 항목 모두 애초에 고려한 대상 사용자가 아니라는 판단에 따라, 이번 5일 간 작업 범위에서 제외한다. 별도 대응 기능을 설계하지 않는다.

### 2. 수치화 유도 장치 부재 — 핵심 기능 구현 후 검토, 확인 필요로 유보

핵심 기능 구현을 먼저 마친 뒤, AI 대화 내용을 분석해 [문제 - 분석 - 해결 과정 - 결과] 형태의 경험 블록으로 정리하고 시각화하는 기능을 추가하는 방향을 검토 중이다. 이 기능이 수치화를 못 하는 사용자에게도 개입 지점을 만들어줄 수 있을 것으로 본다.

지금 시점에는 이 기능을 확정하지 않고, wiki/2026-08-19-강사피드백-기반-한계점-분석.md의 확인 필요 항목으로 유보한다. 핵심 기능 구현 후 시간이 남으면 진행한다.

### 4. 선별 기준 실효성 외부 검증 미완료 — 이번 논의에서 다루지 않음

이번 논의에서는 다루지 않았다. 미결정 상태로 유지한다.

### 5. 커밋 전량 조회·대화 전체 이력 반영에 따른 비용 문제 — 가장 우선순위 높은 문제로 확정

5개 항목 중 가장 우려되는 문제로 확정했다. 사용자 본인의 Repository로 직접 테스트하면서 토큰 소모량을 측정하고, 소모를 줄일 수 있는 구체적인 방법을 확정하는 것으로 진행 방향을 정했다.

강사가 제안한 rtk(Rust Token Killer) 같은 토큰 절감 도구를 적극적으로 활용하는 방향으로 진행한다. 구체적인 적용 지점, 적용 방식, 측정 결과는 별도 문서로 이어서 기록한다.

## 확인 필요

- 2번 경험 블록 시각화 기능의 구체적인 데이터 구조와 화면 설계
- 4번 선별 기준 실효성 검증 방법
- 5번 rtk 등 도구를 적용할 구체적인 지점(Repository 데이터 조회, 대화 이력 프롬프트 구성 등)과 실측 결과
