# Stage A 메시지·stat 선별 계약

## 결정

Stage A는 커밋 SHA와 메시지, 전체 stat, 파일별 경로와 상태 및 stat으로 구성한 경량 커밋과 줄 단위 `contributionItems`를 입력받습니다. 요청 파일에 `patch`가 있으면 크기 상한이 아니라 입력 계약 위반 422로 거부합니다. LLM에도 같은 경량 정보만 전달하며 PR 정보, 작성자와 날짜는 전달하지 않습니다.

LLM은 각 SHA에 `contributionItem`과 `recommended`를 반환합니다. `contributionItem`이 입력 목록의 원문과 정확히 일치하면 `contribution_match` 후보가 됩니다. 기여 항목이 있어도 나머지 커밋 중 설명할 가치가 있으면 `recommended`를 참으로 반환하며, 서버는 라벨이 `null`, `미분류`, 입력 목록에 없는 값 중 무엇이든 `automatic_recommendation` 후보로 정규화합니다. `recommended`가 거짓인 SHA만 미분류로 남습니다.

`미분류`는 LLM 응답의 예약 라벨입니다. 사용자가 같은 문자열을 기여 항목으로 입력해도 `contribution_match`로 해석하지 않습니다.

Stage A 응답은 `candidates`와 `unclassifiedShas`로 구성합니다. 후보는 SHA, 기존 `ExperienceCandidateSource`, 일치한 기여 항목 또는 `null`만 포함합니다. Stage B의 근거, 인용 파일 경로, 관련 SHA, 최대 3개 제한은 포함하지 않습니다.

## 검증과 오류 계약

입력에 없는 SHA가 하나라도 있거나 입력 SHA가 하나라도 누락되면 전체 LLM 결과를 거부합니다. 누락을 미분류로 간주하면 모델의 명시적 판단과 불완전한 응답을 구분할 수 없기 때문입니다. 따라서 `unclassifiedShas`에는 LLM이 반환했고 `recommended`를 거짓으로 명시한 SHA만 포함됩니다. 구조 위반과 중복 SHA도 전체 결과를 거부합니다. 요청 본문은 4.5MB를 넘으면 LLM 호출 전에 거부합니다. GitHub 세션 쿠키는 LLM 비용 노출을 막기 위한 호출 권한 경계로만 사용합니다.

| 상황 | 오류 kind | HTTP status |
| --- | --- | --- |
| 세션 없음 또는 무효 | `unauthorized` | 401 |
| JSON 파싱 실패 | `invalid_json` | 400 |
| 요청 본문 4.5MB 초과 | `body_too_large` | 413 |
| 요청 계약 위반 | `invalid_request` | 422 |
| 구조화 응답 위반 | `schema_validation` | 502 |
| 입력에 없는 SHA | `unknown_sha` | 502 |
| LLM 네트워크 실패 | `llm_network` | 502 |
| LLM 인증 실패 | `llm_auth` | 502 |
| LLM 호출 한도 | `llm_rate_limit` | 503 |
| LLM 타임아웃 | `llm_timeout` | 504 |
| LLM API 키 누락 또는 Groq 404 모델 없음 | `llm_configuration` | 500 |
| Groq 400·409·422 요청 또는 상태 거부 | `llm_request` | 502 |
| 그 밖의 Groq HTTP 실패 | `llm_failure` | 502 |

`llm_network`는 provider 응답을 받기 전의 전송 실패에만 사용합니다. Groq가 HTTP status를 반환한 경우에는 status에 따라 인증, 호출 한도, 타임아웃, 설정, 요청, 일반 실패로 분류합니다.

## 경계

화면의 Loading, Empty, Error 상태 연결은 이슈 #18의 책임입니다. Stage B의 diff 조회와 최종 후보 세 개 선정은 이슈 #17의 책임입니다. 현재 후보 상한 20개는 Vercel Hobby 60초 실행 예산을 위한 초기값이며 확정값이 아닙니다. 상한을 넘긴 응답은 순서대로 절단하지 않고 전체 거부합니다. Stage A 응답 순서는 후보 순위가 아니므로 절단하면 근거 없이 후보를 잃기 때문입니다.

프로덕션 호출자 부재 한계는 이슈 #18에서 해소됐습니다. Repository 분석 상태 머신이 4단계에서 `/api/candidates/stage-a`를 호출합니다. 엔드포인트는 공개적으로 도달할 수 있으므로 GitHub에서 검증한 PAT 세션을 계속 요구합니다. 상태 매핑 결정은 `raw/2026-08-24-후보생성-상태연결-session-log.md`에 있습니다.

Groq 호출은 route의 60초 실행 제한보다 먼저 오류 계약을 반환하도록 55초에 중단합니다. 55초는 플랫폼 종료 전 응답 처리 여유를 둔 미검증 초기값이며 이슈 #19에서 실제 실행 시간과 함께 확정해야 합니다.

## 확인 필요

- `llama-3.3-70b-versatile` 모델과 `GROQ_API_KEY` 환경 변수 조합은 실데이터 검증 전에 확정해야 합니다.
- 후보 상한 20개가 60초 안에서 안정적으로 동작하는지는 이슈 #19에서 측정해야 합니다.
- 요청이 4.5MB에 가까울 때 메모리 사용량과 커밋 수 상한이 필요한지 확인해야 합니다.
- 입력 커밋이 많을 때 청크 분할이 필요한지와 분할 결과의 병합·재판단 정책은 실측 후 정해야 합니다.
- 기여 항목과 커밋 메시지의 용어가 다른 경우 정확한 의미 매칭 품질은 확인이 필요합니다.
- Vercel Hobby의 실제 실행 제한과 Stage A 55초 중단 시한이 충분한 응답 여유를 제공하는지 확인이 필요합니다.
