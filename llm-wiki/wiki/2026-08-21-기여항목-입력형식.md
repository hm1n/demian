# 기여 항목 입력 형식

## 결정

Repository 입력 화면의 본인 기여 항목은 선택형 자유 텍스트로 받고, 한 줄을 하나의 항목으로 해석합니다. 화면은 원문을 state에 보관하고, `parseContributionItems`가 각 줄의 앞뒤 공백과 빈 줄을 제거한 문자열 배열을 만듭니다. 입력을 생략해도 기존 Repository 분석을 그대로 시작합니다.

## 근거

- Stage A는 사용자 기여 항목별 커밋 분류가 필요하므로 항목 경계를 보존해야 합니다.
- 한 개의 textarea는 동적으로 입력 행을 추가하는 구조화 UI보다 구현과 사용이 단순합니다.
- 줄 단위 배열은 입력 있음, 없음, 일부 입력을 같은 전달 형식으로 표현할 수 있습니다.
- 이슈 #21에서는 실제 소비자가 없는 선택형 callback을 만들지 않습니다. 소비자가 생기기 전에 연결 경계를 추가하면 사용자가 입력한 값이 전달된다고 오해할 수 있고 speculative scaffolding이 되기 때문입니다.

## 이슈 #16 연결 지점

Stage A를 구현하는 이슈 #16에서 `contributionItems` state의 현재 값을 `parseContributionItems`로 변환하고 후보 생성 오케스트레이터에 전달합니다. 이슈 #21은 입력 state와 파싱 계약까지만 제공합니다.

## 알려진 한계와 확인 필요

- 기여 항목과 커밋 메시지의 용어가 다른 경우의 의미 매칭은 이 입력 화면에서 처리하지 않습니다. Stage A의 LLM 판단 방식으로 확인이 필요합니다.
- 사용자가 실제 기여 중 일부만 입력했는지는 UI에서 판별하지 않습니다. Stage A가 입력된 항목과 미분류 커밋을 함께 다루는 방식은 후속 실험으로 확인이 필요합니다.
