# Repository 조회 상태 정책

## Empty 상태

Empty 안내는 Repository를 선택한 시점이 아니라 실제 조회 결과가 0개로 확인된 뒤에 표시합니다. 선택 시점에는 커밋 유무를 알 수 없으므로 미리 안내하면 Repository에서 확인되지 않은 값을 추정하게 됩니다.

전체 커밋이 0개이면 `분석할 커밋이 없습니다`라고 안내합니다. 전체 커밋은 있지만 블랙리스트 필터를 통과한 커밋이 0개이면 `이 저장소는 분석하기 어렵습니다`라고 안내합니다. 두 경우 모두 커밋 이력이 있는 다른 Repository를 선택할 수 있는 버튼을 제공합니다.

커밋이 매우 적더라도 0개가 아니고 필터를 통과한 커밋이 하나 이상이면 정상 조회를 계속합니다. 커밋 수를 분석 가능성의 대리 지표로 쓰지 않으며 별도 최소 개수 기준을 두지 않습니다.

필터를 통과한 커밋이 없으면 상세 조회와 파일 트리 대체 분석을 호출하지 않습니다. 다른 Repository를 선택하도록 안내합니다.

## Loading 상태

전체 커밋 조회를 1단계, 상세 데이터 조회를 2단계, 파생 지표 계산을 3단계로 표시합니다. 2단계의 커밋 상세 조회 중에는 완료 개수와 전체 대상 개수를 표시합니다. 이어지는 언어 통계와 파일 트리 조회도 상세 데이터 수집에 포함하되 문구를 구분합니다.

3단계는 수집 결과를 후보 데이터 입력 형태로 조립하기 직전에 표시합니다. 브라우저가 해당 상태를 실제로 그릴 기회를 한 번 제공한 뒤 동기 조립을 수행합니다.

## Error 상태와 복구

오류 화면의 복구 버튼은 오류 안내 바로 아래에 둡니다. 현재 라이브러리는 안전한 부분 재개 커서를 제공하지 않으므로 부분 결과는 이어 쓰지 않습니다. 호출 한도나 네트워크 오류는 같은 Repository에서 다시 시작하고, 인증 취소는 인증을 다시 진행한 뒤 처음부터 시작하며, Repository 미존재는 다른 Repository를 선택한 뒤 처음부터 조회합니다.

- `rate_limit`은 호출 한도가 회복된 뒤 전체 조회를 다시 시도하도록 안내합니다.
- `auth_revoked`는 기존 토큰을 입력 화면에서 지우고 새 인증 정보를 입력하도록 안내합니다. 사용자가 새 토큰을 제출하면 전체 조회를 처음부터 재개합니다. OAuth 인증 흐름은 현재 화면에 없으므로 이번 이슈에서 추가하지 않습니다.
- `repo_not_found`는 삭제, 이름 변경, 현재 인증의 접근 가능 여부를 확인하도록 안내하고 Repository 입력으로 돌아갑니다.
- `partial_failure`는 수집 완료 개수와 가능한 경우 전체 대상 개수를 표시합니다. `cause`에 보존된 원래 오류를 따라 호출 한도나 인증 취소 같은 실제 원인도 함께 안내합니다.
- `network`와 `server_error`는 실패 원인을 구분해 안내하고 같은 Repository의 전체 조회 재시도 버튼을 제공합니다.

전체 커밋 페이지네이션에서 일부 결과를 수집한 뒤 실패한 경우에도 원래 오류 종류를 `cause`로 보존합니다. 이 정보는 사용자에게 부분 실패의 실제 원인을 안내하기 위한 근거로만 사용합니다.

## 범위 경계

이번 구현은 조회 상태 오케스트레이션과 안내 화면만 추가합니다. 전체 커밋 상한, 상세 조회 병렬화, 응답 크기 제한, 422 세분화, 파일 트리 404 재확인, `changedFiles` 불일치는 기존 backlog에 그대로 남깁니다. 점수 계산, 순위 결정, 최종 후보 선별도 수행하지 않습니다.
