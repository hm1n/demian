# 경험 선택 확정 상태 계약

## 문서 목적

이슈 #55가 확정한 인터뷰 대상 확정 상태와 진입점 배선을 기록합니다. 구현은 `src/features/experience-candidates/experience-selection.ts`, `experience-interview-entry.tsx`, `experience-candidate-detail.tsx`, `experience-candidate-list.tsx`에 있습니다.

## 상태를 어디에 두었는가

확정 상태 `ExperienceSelectionState`는 `AnalysisState`에 넣지 않고 후보 기능 안에 두었습니다. Repository 분석 진행 상태와 인터뷰 대상 확정은 서로 다른 축입니다. `AnalysisState`에 얹으면 분석을 다시 실행할 때 확정 상태가 함께 초기화됩니다.

상태 보유 위치는 `ExperienceCandidateList`입니다. 상세 진입 상태(`selectedSha`)와 같은 컴포넌트에 두어 목록 복귀 시 두 값을 한 함수에서 함께 비웁니다.

`setSelectedSha`는 상세 화면 진입 상태이고 인터뷰 대상 확정이 아닙니다. 두 값을 분리해 두었기 때문에 상세를 보다가 목록으로 돌아가면 확정도 함께 사라집니다. 확정 상태를 유지하려면 저장 계층이 필요하고 그것은 `wiki/2026-08-24-경험선택-세션저장-후속-backlog.md`의 범위입니다.

## 진입점과 재선택

진입점은 상세 화면의 `인터뷰 시작` 절에 둔 `이 경험으로 인터뷰 시작` 버튼입니다. 기능 정의서 사용자 흐름이 "상세 화면에서 근거를 확인한다" 다음에 선택을 두기 때문에 근거 섹션 뒤에 배치했습니다.

확정 시점에 `confirmExperienceSelection`이 `buildExperienceEvidenceSnapshot`을 호출합니다. 목록으로 돌아가 다른 경험을 확정하면 새 값이 이전 확정을 그대로 교체합니다. 이전 확정을 보존하지 않습니다. 보존은 세션 저장에 의존하므로 이번 범위가 아닙니다.

라우팅은 추가하지 않았습니다. 이슈 #45의 결정을 유지합니다. 후보 데이터가 `AnalysisState` 메모리에만 있어서 URL 직접 진입은 분석을 처음부터 다시 실행해야 하고, Stage B가 쓰는 Gemini 무료 등급은 하루 20요청을 프로젝트 전체가 공유합니다.

## 확정 이후 화면은 임시 자리다

`ExperienceInterviewEntry`는 인터뷰 화면 본체가 아닙니다. `실제 코드 기반 AI 질문 생성` 이슈가 이 컴포넌트 자리를 본체로 대체합니다. 대체 시점과 이유는 컴포넌트 주석에 남겼습니다. 다음 작업자가 완성된 화면으로 오해해 위에 기능을 덧붙이지 않도록 화면에도 "질문은 아직 생성되지 않습니다" 안내를 표시합니다.

이 화면은 확정된 근거 규모만 보여 줍니다. 대표 커밋의 변경 파일 개수에만 `확인 가능` 태그를 붙이고, 관련 커밋과 인용 파일 개수에는 `AI 선택` 태그를 붙입니다. 이슈 #47 PR #52 재검증 P2가 정한 경계를 새 화면에서도 지킵니다.

처음 안은 대표 커밋과 관련 커밋의 변경 파일을 합친 개수에 `확인 가능`을 붙였습니다. PR #57 1차 리뷰가 P2로 지적했고 이 PR의 Acceptance Criteria를 직접 위반하므로 같은 PR에서 고쳤습니다. 관련 커밋은 AI가 고른 값이라 합계도 그 선택에 따라 달라지는데, `확인 가능`으로 표시하면 Repository 사실처럼 보입니다. 합계를 없애고 대표 커밋 개수만 표시합니다.

## Loading, Empty, Error

**Loading을 따로 만들지 않았습니다.** 스냅샷 생성은 LLM을 호출하지 않는 동기 순수 함수여서 관측할 진행 상태가 없습니다. 없는 단계를 시간 같은 대리 지표로 만들어 보여 주지 않는 기존 결정을 따릅니다. 근거는 `repository-analysis.ts`의 `stage_b` 주석입니다. 선택 흐름의 Loading은 분석 Loading이 담당하고, 그 동안 후보 목록과 선택 액션은 렌더링되지 않습니다.

**Empty도 새로 만들지 않았습니다.** 최종 후보 0개는 `no_final_candidates` Empty가 처리하므로 후보 목록과 선택 액션에 도달하지 않습니다. 그 상태에서 선택 액션이 노출되지 않는다는 사실을 `repository-analysis-view.test.tsx`의 기존 Empty 테스트에 회귀 검증으로 추가했습니다.

**Error는 근거 스냅샷을 만들지 못한 경우입니다.** 사유는 `representative_commit_not_indexed`, `no_repository_evidence`, `evidence_input_too_large` 세 가지이고 문구는 `EXPERIENCE_SELECTION_ERROR_COPY`에 있습니다. `role="alert"`로 알리고 `data-selection-error` 속성에 사유를 남깁니다. 목록 복귀 버튼이 같은 화면에 있으므로 별도 복구 액션을 추가하지 않았습니다. 목록으로 돌아가면 실패 안내도 함께 사라집니다.

이슈 #55 Approach는 Error 대상으로 "근거 상한 초과"도 들었습니다. 상한 초과는 두 갈래로 갈라 처리합니다. patch가 잘리는 것은 정상 상태이므로 실패로 올리지 않고 확정 화면이 상한과 실제로 실은 분량을 함께 표시합니다. patch를 전부 빼도 커밋 메시지와 변경 파일 목록만으로 상한을 넘는 경우는 잘라서 해결할 수 없으므로 `evidence_input_too_large` Error로 올립니다. 이 구분은 PR #56 1차 리뷰 P1을 반영해 확정했고 근거는 `wiki/2026-08-24-선택경험-근거-인계-계약.md`에 있습니다.

## 접근성

선택 액션의 접근성 이름은 버튼 문구 `이 경험으로 인터뷰 시작`으로 짧게 두고, 확인 가능·불가 안내는 `aria-describedby`로 접근성 설명에 연결했습니다. `aria-label`로 이름만 주면 안내가 스크린리더에서 사라집니다. 그것이 이슈 #47 PR #52 1차 리뷰의 P1이었고 같은 실수를 새 액션에서 반복하지 않았습니다.

## 하지 않은 것

- 질문 생성, 스트리밍 출력, 인터뷰 화면 본체를 만들지 않았습니다.
- 서버 저장, API 라우트, 라우팅을 추가하지 않았습니다.
- 세션 이어가기, 재방문 복원, 여러 탭 처리를 다루지 않았습니다.
- 새 의존성을 추가하지 않았습니다.

## 확인 필요

- 확정 화면의 근거 요약 항목이 사용자에게 충분한지는 확인되지 않았습니다. 질문 생성 이슈가 이 화면을 대체할 때 다시 판단해야 합니다.
- 확정 상태가 목록 복귀로 사라지는 동작이 사용자 기대와 맞는지는 확인되지 않았습니다. 유지하려면 저장 계층이 필요합니다.
