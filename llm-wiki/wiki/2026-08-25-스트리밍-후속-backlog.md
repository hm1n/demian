# 질문 스트리밍 후속 backlog

## 문서 목적

이슈 #60 PR #61의 재검증 라운드에서 나온 지적 가운데 이번 PR에서 반영하지 않은 항목을 기록합니다. `wiki/2026-08-20-코드리뷰-전략.md`의 종료 기준에 따라 재검증에서 새로 나온 P2는 후속으로 분리하고 라운드를 더 늘리지 않습니다. 같은 문서의 2026-08-20 결정에 따라 새 GitHub Issue를 만들지 않고 여기서 추적합니다.

## 미뤄 둔 항목

### 1. 청크 없이 `done`으로 끝난 스트림의 화면 상태

`done`이 `seq: 0`으로 오고 청크가 하나도 없으면 수신부는 이를 정상 완료로 받아들입니다. 이때 화면은 `messages`가 빈 채로 Loading 문구가 사라지고 상태 문단만 `질문이 모두 도착했습니다.`로 남습니다. 빈 로그와 완료 안내가 함께 보이는 상태입니다.

**이번 PR에서 고치지 않은 이유는 세 가지입니다.**

첫째, 현재 범위에서 도달할 수 없습니다. 스트림 소스는 `test-stream.ts` 하나이고 `done`은 루프를 끝까지 돈 뒤 `TEST_STREAM_CHUNKS.length`로만 보냅니다. 이 값은 0이 될 수 없습니다. `AGENTS.md`의 Code Review Rules는 방어 코드를 추가할 때 그 코드가 실제로 도달 가능한지 확인하라고 적고 있습니다. 도달 가능해지는 시점은 실제 생성 스트림이 붙는 이슈 #59입니다.

둘째, 수정 비용이 코드에 있지 않습니다. 기능 정의서 `실시간 AI Streaming 응답`은 Empty를 "이 기능은 화면에 표시할 응답이 생성되는 경우에만 동작하므로 별도의 빈 상태는 없습니다"로 **명시적으로 결정**했습니다. 청크 없는 `done`은 그 결정의 전제를 깨는 경로이므로, 화면 분기를 추가하기 전에 이 경로를 Empty로 볼지 Error로 볼지부터 정해야 합니다. 정하면 노션 기능 정의서의 Empty 절도 함께 갱신해야 합니다. 코드 한 줄이 아니라 정의서 결정입니다.

셋째, 판단에 필요한 사실이 아직 없습니다. 실제 LLM 스트림이 내용 없이 `done`을 보내는 경우가 무엇인지(빈 응답, 안전 필터, 즉시 중단) 확인되지 않았습니다. 사유에 따라 사용자에게 줄 안내가 갈립니다.

**이슈 #59에서 함께 정해야 하는 것은 다음과 같습니다.**

- 청크 없는 `done`을 Empty로 볼지 Error로 볼지
- Error로 본다면 어떤 `kind`를 쓸지. 전송 문제가 아니므로 `stream_connect_failed`와 `stream_interrupted` 어느 쪽도 맞지 않습니다
- 결정에 맞춘 기능 정의서 Empty 절 갱신
- 회귀 테스트

## 반영한 항목

기록을 위해 같은 라운드에서 반영한 항목도 남깁니다.

- **청크 0개 상태의 단절 분류** (`interview-stream-client.ts`). 2xx로 열린 본문이 첫 청크 전에 닫히면 `stream_interrupted`로 두어, 이어받을 내용이 없는데도 "받은 지점부터 이어받습니다"라고 안내했습니다. 받은 청크가 있는지로 갈라 `stream_connect_failed`로 두었습니다. `wiki/2026-08-20-코드리뷰-전략.md`의 예외 조건 가운데 "수정 비용이 매우 작은 경우"에 해당해 같은 PR에서 반영했습니다. 파일 안에 이미 같은 삼항이 두 곳 있어 패턴도 같습니다.

## 미루면서 생기는 대가

- 실제 생성 스트림이 내용 없이 끝나면 사용자는 빈 화면과 `질문이 모두 도착했습니다.` 안내를 함께 봅니다. 무엇이 잘못됐는지 알 방법이 없고 다시 시도 버튼도 나타나지 않습니다.
- 이슈 #59가 이 경로를 만나기 전에 정의서 결정을 먼저 해야 합니다. 구현 도중에 발견하면 그 자리에서 정의서 갱신 승인을 기다리게 됩니다.

## 확인 필요

- 청크 없는 `done`을 Empty로 둘지 Error로 둘지는 사용자 결정이 필요합니다. 기능 정의서의 명시적 결정을 바꾸는 일입니다.
- 실제 provider가 내용 없이 스트림을 끝내는 조건은 확인되지 않았습니다. 이슈 #59에서 provider를 확정한 뒤 실측해야 합니다.
