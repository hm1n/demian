# Wave 0 머지 후 기여 항목 테스트 실패

## 발생한 문제

Wave 0의 PR #23, #24, #25, #26을 각각 검증한 뒤 `develop`에 합치자 `repository-analysis-view.test.tsx`의 기여 항목 테스트 3건이 실패했다.

이슈 #13에서 Repository 분석 전에 `POST /api/auth/session` 요청을 추가하면서 `startAnalysis`가 비동기 함수가 됐다. 이슈 #21에서 추가한 세 테스트는 동기 흐름을 전제로 `submitRepository()`를 `await`하지 않아, 세션 요청과 `analyzeRepository` 호출이 끝나기 전에 assertion을 실행했다. 그 결과 첫 테스트는 분석 호출을 확인하지 못했고, 나머지 두 테스트는 아직 Error 또는 Empty 화면이 렌더되지 않아 후속 버튼을 찾지 못했다.

또한 공통 헬퍼 `fillRepository()`가 입력하는 토큰은 `github_pat_secret_value`로 바뀌었지만 첫 테스트는 이전 값인 `token`을 기대했다. 토큰 값을 공통 상수로 옮겨 헬퍼와 assertion이 같은 값을 참조하도록 정정했다.

## 병렬 PR 리뷰가 놓친 이유

각 PR은 자기 변경만 포함한 상태에서 테스트가 통과했다. 이슈 #13의 비동기 제출 변경과 이슈 #21의 테스트 추가가 서로 다른 PR에 있었기 때문에 어느 PR의 diff에도 합쳐진 뒤의 불일치가 나타나지 않았다. 개별 diff 중심 리뷰만으로는 같은 파일의 최종 상태와 PR 사이 계약 변경을 확인할 수 없었다.

## 확인 절차

병렬 작업에서 같은 파일이나 같은 데이터 흐름을 여러 PR이 수정하면 다음 Wave로 넘어가기 전에 통합 브랜치에서 확인한다.

1. 모든 PR을 합친 최종 파일의 호출자와 헬퍼를 함께 읽고, 동기·비동기 계약과 공통 픽스처 값이 일치하는지 확인한다.
2. 변경된 비동기 함수의 모든 호출부에서 완료를 기다리는지 검색한다.
3. 공통 헬퍼가 입력하는 값을 assertion에 별도 리터럴로 중복하지 않는다.
4. 통합 브랜치에서 전체 테스트, lint, typecheck를 실행해 개별 PR 검증으로 드러나지 않은 교차 영향을 확인한다.
