# PAT 세션 쿠키 정책

PAT 세션은 별도 서버 저장소를 사용하지 않고 AES-256-GCM으로 암호화한 값을 `github_session` 쿠키에 저장합니다. 세션 발급 전에 GitHub 인증 사용자 API로 PAT가 실제로 유효한지 검증하며, 유효하지 않으면 401, GitHub rate limit이면 429, 그 밖의 조회 실패는 502를 반환하고 쿠키를 발급하지 않습니다. 쿠키에는 `HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/` 속성을 적용합니다. 서버 공통 유틸은 요청의 쿠키에서만 토큰을 읽으며, 쿠키가 없거나 변조된 경우 기존 `auth_revoked` 오류로 처리합니다.

암호화 키는 코드에 저장하지 않고 `GITHUB_SESSION_ENCRYPTION_KEY` 환경 변수에서 읽습니다. 값은 base64로 인코딩한 32바이트 키여야 합니다.

## 확인 필요

`GITHUB_SESSION_ENCRYPTION_KEY`라는 환경 변수 이름과 Vercel 운영 환경에서 키를 생성하고 교체하는 절차는 확정이 필요합니다. 키를 교체하면 기존 쿠키를 복호화할 수 없으므로 사용자는 인증 정보를 다시 입력해야 합니다.

세션 발급 뒤 PAT가 폐기되면 암호화 쿠키는 만료 전까지 복호화됩니다. Stage A는 PAT를 GitHub API 호출에 사용하지 않으므로 폐기 직후에도 Groq 호출 권한이 남는 한계가 있으며, 재검증 주기나 세션 만료 정책은 확인이 필요합니다.

GitHub 조회 로직의 서버 route handler 이관은 이 정책의 범위가 아닙니다. 이관 전까지 기존 조회 함수가 입력 직후의 PAT를 사용하는 과도기적 경계가 남아 있습니다. 후속 이슈 #14에서 GitHub 조회가 서버 공통 유틸만 사용하도록 연결하면 조회와 재시도 중 PAT 보관을 제거할 수 있습니다. PAT 입력 자체를 브라우저 JavaScript에서 제거하는 작업은 OAuth 전환 이슈 #22의 범위입니다.
