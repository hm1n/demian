# 경험 후보 출력 스키마

## 목적과 범위

Stage A와 Stage B가 생성한 구조화 응답을 동일한 계약으로 검증하고, 화면과 후속 상태 연결 단계에 근거가 확인된 경험 후보만 전달합니다. 출력 단계는 후보 선정 규칙이나 LLM 호출을 수행하지 않으며 점수, 가중치, 순위도 계산하지 않습니다.

근거는 GitHub 이슈 #15와 부모 기능 정의서인 GitHub 이슈 #12입니다. 확인 날짜는 2026-08-21입니다.

## 출력 인터페이스

`ExperienceCandidateOutput`은 후보 목록과 후보 부족 사유로 구성됩니다.

| 필드 | 타입 | 필수 | 의미 |
| --- | --- | --- | --- |
| `candidates` | `readonly ExperienceCandidate[]` | 필수 | 검증을 통과한 경험 후보 목록이며 최대 3개입니다. 대표 SHA는 후보마다 달라야 합니다. |
| `insufficientCandidatesReason` | `string \| null` | 필수 | 후보가 3개 미만인 이유입니다. 후보가 3개이면 `null`입니다. |

각 `ExperienceCandidate`는 다음 근거 필드를 포함합니다.

| 필드 | 타입 | 필수 | 의미 |
| --- | --- | --- | --- |
| `sha` | `string` | 필수 | 경험을 대표하는 커밋 SHA입니다. |
| `relatedShas` | `readonly string[]` | 필수 | 같은 PR에 속해 근거를 보강하는 관련 커밋 SHA 목록입니다. |
| `evidence` | `string` | 필수 | 실제 커밋과 파일을 근거로 한 후보 선정 설명입니다. |
| `citedFilePaths` | `readonly string[]` | 필수 | 근거에서 인용한 Repository 파일 경로입니다. |
| `source` | `"contribution_match" \| "automatic_recommendation"` | 필수 | 사용자 기여 항목 매칭 후보와 자동 추천 후보를 구분합니다. |

## 화면 근거 출처

후보 목록의 화면 데이터 모델은 근거 출처를 `EvidenceOrigin`으로 구분합니다. MVP에서는 Repository에서 수집하고 검증한 근거만 표시하므로 `"repository"` 한 값만 사용하며, 이후 보조 메모가 범위에 포함되면 `"user_note"` 같은 값을 유니온에 추가할 수 있습니다. 후보 생성 경로를 나타내는 `ExperienceCandidate.source`와 근거의 출처를 나타내는 `EvidenceOrigin`은 서로 다른 필드입니다.

## 검증과 오류 계약

`experienceCandidateOutputSchema`는 AI SDK의 `generateObject`와 `streamObject`에 공통으로 전달할 JSON Schema입니다. `validateExperienceCandidateOutput`은 이미 역직렬화된 값을, `parseExperienceCandidateOutput`은 JSON 텍스트를 같은 계약으로 검증합니다. 정의되지 않은 필드와 빈 문자열은 허용하지 않습니다.

검증 실패는 `ExperienceCandidateOutputError`로 변환합니다. `kind`는 JSON 문법 오류인 `json_parse`, 출력 구조 위반인 `schema_validation`, 입력에 없는 SHA인 `unknown_sha`를 구분합니다. 원래 오류는 `cause`로 보존합니다.

## SHA 무결성과 책임 경계

`assertCandidateShas`는 대표 커밋 `sha`와 모든 `relatedShas`를 해당 Stage에 전달된 입력 SHA 집합과 대조합니다. 입력에 없는 SHA가 하나라도 있으면 `unknown_sha` 오류를 던져 전체 결과를 거부하며, 유효한 후보만 부분적으로 통과시키지 않습니다.

Stage B의 `assertCandidateEvidence`는 SHA 검증에 더해 관련 SHA가 대표 커밋과 같은 PR에 속하는지 확인합니다. 인용 파일 경로는 Repository 파일 트리 또는 해당 후보의 대표·관련 커밋 변경 파일에 존재해야 합니다. 관계나 경로가 하나라도 맞지 않으면 각각 `unrelated_sha`, `unknown_file_path` 오류로 전체 결과를 거부합니다.

관련 커밋은 GitHub PR 소속 정보만 근거로 합니다. 시간 근접성, 파일 경로 중복, 커밋 메시지의 이슈 번호로 관계를 추정하지 않습니다. 실제 후보 선정, 프롬프트 구성, LLM 호출, route handler와 후보 화면 연결은 후속 이슈의 책임입니다.
