# 경험 선택 세션 저장·이어가기 후속 backlog

## 문서 목적

부모 이슈 #53 `경험 선택`이 이번 범위에서 제외한 항목을 기록합니다. 제외 결정의 근거와 미루면서 생기는 대가를 함께 남깁니다. 2026-08-20 코드 리뷰 전략에 따라 새 GitHub Issue를 만들지 않고 이 문서에서 추적합니다.

## 왜 미뤘는가

기능 정의서는 2026-08-19 설계 시점 문서라서 서버 저장 전제가 그대로 남아 있었습니다. 2026-08-24 레포 기준으로 점검한 결과 다음이 확인되었습니다.

- 서버 저장소가 없습니다. `package.json`에 DB나 KV 의존성이 없고 `src`에 저장 계층이 없습니다. PAT 세션도 서버 저장 없이 암호화 쿠키만 씁니다.
- 재방문에 쓸 사용자 식별자가 없습니다. `github_session` 쿠키에 `Max-Age`가 없어 브라우저를 닫으면 세션이 사라집니다. 재방문 유지는 GitHub OAuth 전환 이슈 #22 없이는 검증 자체가 불가능합니다.
- 후보 재생성이 사실상 불가능합니다. Stage B가 쓰는 Gemini 무료 등급의 `GenerateRequestsPerDayPerProjectPerModel-FreeTier` quotaValue는 20이고 프로젝트 전체가 공유합니다. 따라서 "재방문해도 대화를 이어 본다"는 대화 세션만 저장해서는 성립하지 않고 후보와 근거 스냅샷 자체를 저장해야 합니다.

우선순위가 높은 `실제 코드 기반 AI 질문 생성`과 `실시간 AI Streaming 응답`을 먼저 진행하기 위해, 경험 선택은 두 기능이 실제로 필요로 하는 최소 단위만 만들기로 했습니다.

## 미뤄 둔 항목

### 1. 경험별 대화 세션 서버 저장

경험 하나에 붙는 인터뷰 대화를 서버에 저장합니다. 결정해야 할 것은 저장소 선택, 후보 스냅샷 저장 여부, 후보 식별자 계약, 보관 기간과 삭제 기준입니다.

저장소 선택은 새 의존성 결정입니다. 현재 레포는 새 의존성을 추가하지 않는 제약을 지키고 있으므로 사용자와 리드의 승인이 먼저 필요합니다.

후보 식별자도 계약이 없습니다. 후보는 대표 커밋 `sha`만 가지고, 한 번의 분석 실행 안에서는 유일하지만 저장 키로 쓰기에는 부족합니다. 같은 저장소를 다시 분석하면 같은 `sha`로 다른 근거 스냅샷이 나올 수 있습니다.

### 2. 세션 이어가기와 재방문 복원

재선택 시 저장된 대화를 불러오고, 경험을 전환해도 이전 세션을 보존하고, 재방문 시 복원하고, 여러 탭에서 같은 세션을 연 경우를 처리합니다.

이 항목은 1번과 사용자 식별자 이슈 #22에 동시에 의존합니다. 식별자가 없으면 "누구의 세션인지" 자체를 정의할 수 없어 구현해도 검증할 수 없습니다.

### 3. 스트리밍 이탈 후 서버 지속 생성

`실시간 AI Streaming 응답`의 결정 사항 가운데 "클라이언트 연결이 끊겨도 서버가 생성을 계속하고 완성된 응답을 저장한다" 항목입니다. 세션 저장, 후보 스냅샷 저장, 사용자 식별자 세 가지에 동시에 의존하므로 그 기능에서 별도 이슈로 분리합니다.

막는 것은 플랫폼이 아닙니다. Vercel Hobby 함수 상한은 300초이고 라우트에 걸린 60초는 우리가 스스로 건 제약입니다. 막는 것은 저장 계층과 식별 계층입니다.

## 미루면서 생기는 대가

- 브라우저를 닫거나 페이지를 떠나면 대화가 사라집니다.
- 다시 돌아왔을 때 질문을 다시 만들어야 합니다. 질문 생성 provider 선택에서 이 비용을 고려해야 합니다.
- 후보 스냅샷도 메모리에만 있습니다. 라우팅이 없고 후보 데이터가 `AnalysisState` 메모리에만 있어서, URL 직접 진입은 분석을 처음부터 다시 실행해야 합니다. Gemini 하루 20요청 제약과 겹쳐 사실상 재현이 어렵습니다.

## 확인 필요

- 저장소 도입 시점과 후보 형태를 정하지 않았습니다. 사용자 결정이 필요합니다.
- 질문 생성 provider는 Gemini가 아니라 Groq를 검토합니다. Gemini 무료 등급은 하루 20요청을 프로젝트 전체가 공유하고 Stage B가 이미 그 쿼터를 쓰기 때문입니다. Groq는 요청 수가 아니라 8,000 TPM에 걸립니다. 이 판단은 질문 생성 이슈에서 확정합니다.
- Notion 기능 정의서 `경험 선택` 본문은 아직 서버 저장 전제가 그대로입니다. 갱신은 사용자 승인을 받지 않았으므로 하지 않았습니다.
