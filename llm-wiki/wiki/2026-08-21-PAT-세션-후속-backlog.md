# PAT 세션 후속 backlog

## 조회와 재시도 중 과도기 PAT 참조 제거

- 등급: P2
- 현상: 세션 쿠키를 발급한 뒤에도 기존 클라이언트 GitHub 조회와 같은 Repository 재시도를 위해 PAT를 React state에 보관합니다.
- 분리 근거: 브라우저 JavaScript에서 PAT를 완전히 제거하려면 GitHub 조회를 서버 route handler로 옮겨야 하며, 이는 이슈 #14의 명시된 범위입니다. 현재 PR에서 수정하면 병렬 작업의 파일 경계와 범위 밖 금지 규칙을 위반합니다.
- 승격 경로: 이슈 #14에서 모든 GitHub 조회가 `getGitHubTokenFromRequest()`만 사용하도록 바꾸고 `sessionToken` state와 클라이언트 `GitHubAuth.token` 전달을 삭제합니다. PAT 입력 자체의 브라우저 JavaScript 노출은 OAuth 전환 이슈 #22에서 제거합니다.

## 공백 PAT의 422 복구 분류

- 등급: P2
- 현상: 브라우저의 `required` 검증은 공백 문자열을 허용하고 세션 API는 422를 반환하지만, 화면은 이를 일시적 서버 오류와 전체 재시도로 안내합니다. 사용자는 입력 필드에서 값을 고칠 수 있으나 오류 원인과 복구 안내가 정확하지 않습니다.
- 분리 근거: 재검증 리뷰에서 발견된 non-blocking 입력 검증 문제이며 이슈 #13의 Acceptance Criteria를 직접 위반하지 않습니다. 코드리뷰 전략의 재검증 종료 기준에 따라 새 P2는 이번 라운드에서 수정하지 않고 후속으로 분리합니다.
- 발생 구분: 422 상태 분류 누락은 원래 구현에 있었고, 직전 리뷰 수정이 복구 동작을 `reauthenticate`에서 `retry`로 바꾸면서 동일한 공백 값 재전송이 더 두드러졌습니다.
- 승격 경로: 세션 발급 클라이언트가 422를 입력 오류로 구분하고 PAT 입력에 초점을 돌리는 회귀 테스트와 함께 수정합니다.
