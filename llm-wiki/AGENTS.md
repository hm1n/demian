# llm-wiki 작업 규칙

## 기본 구조

- `raw/`는 시간축이다. 그 시점에 무슨 말이 나왔고 무슨 일이 있었는지를 날짜순으로 쌓고 이후 고치지 않는다. 프로젝트 밖에서 온 원본 자료와 세션 로그가 모두 여기에 들어간다.
- `wiki/`는 주제축이다. 한 주제의 현재 결론을 한 문서에 모으고 계속 갱신한다.
- `output/`은 보고서, 요약문, 실행 계획 같은 산출물을 보관하는 곳이다.

### 어디에 쓸지 판정하는 기준

- 나중에 고칠 일이 없는 내용이면 `raw/`다. 계속 갱신될 내용이면 `wiki/`다.
- 날짜가 의미를 가지면 `raw/`다. 주제가 의미를 가지면 `wiki/`다.
- 한 세션의 측정 과정, 시도와 실패, 리뷰 라운드별 반영 경위는 `raw/`다. 그 세션이 도달한 계약과 정책은 `wiki/`다.

## 세션 로그 작성

- 결정, 정정, 실측 중 하나라도 생기면 `raw/`에 세션 로그를 남긴다.
- 파일은 주제 단위로 만든다. 한 세션이 주제 두 개를 다뤘으면 파일도 두 개다. 서로 다른 주제를 한 파일에 합치지 않는다.
- 쓰는 시점은 세션의 끝이 아니라 그 주제의 작업이 마무리되는 시점이다. 세션 끝까지 미루면 앞에서 다룬 주제의 경위가 이미 흐려져 있다.
- 한 주제가 여러 세션에 걸치면 세션마다 파일을 새로 만든다. 이전 파일에 덧붙이지 않고, 새 파일에 어떤 파일을 이어받는지 참조를 남긴다.
- 세션 로그에는 그 세션에서 무엇을 재고 무엇을 시도했고 무엇이 실패했는지를 시간순으로 적는다. 결론만 적지 않는다.
- 접은 대안과 그 이유를 함께 적는다. 이 정보는 `wiki/`에 남지 않으므로 여기서 빠지면 사라진다.
- 세션 로그를 `wiki/` 문서 안에 절로 넣지 않는다. `wiki/`는 결론을 담고 경위는 `raw/` 링크로 가리킨다.
- 하루가 지난 뒤에 소급해서 세션 로그를 만들지 않는다. 그 시점 정보가 이미 없으므로 결론에서 거꾸로 만든 기록이 되어 `raw/`의 뜻에 어긋난다. 빠진 세션은 빠진 채로 두고 `log.md`에 사실만 남긴다.

## 원본 보존

- `raw/` 안의 원본 자료는 임의로 덮어쓰지 않는다.
- 한 번 생성한 `raw/` 파일은 이후 수정하지 않는다.
- 원본에서 오류를 발견하거나 수정 사항과 후속 논의가 발생하면 기존 파일을 고치지 않고 새로운 `raw/` 파일에 기록한다.
- 새 파일에는 어떤 기존 자료를 보완하거나 정정하는지 참조를 남긴다.
- 원본 자료의 출처, 확인 날짜, 버전 정보가 보이면 유지한다.
- `raw/` 파일명은 폴더로 나누지 않고 `{YYYY-MM-DD}-{주제}.md` 형식으로 짓는다. 같은 날짜에 여러 자료가 생겨도 주제로 구분한다.
- 새로 만드는 세션 로그는 `{YYYY-MM-DD}-{주제}-session-log.md` 형식으로 짓고 접미사를 반드시 붙인다. 목록만 보고 외부 원본과 세션 로그를 구분할 수 있어야 한다.
- 기존 `raw/` 파일명은 바꾸지 않는다. `wiki/` 문서 11개와 `log.md`가 걸어 둔 링크가 깨진다.
- 새로 만드는 `raw/`와 `wiki/` 문서는 `~합니다` 존댓말로 쓴다. 기존 문서의 종결 어미는 고치지 않는다.

## 위키 작성

- `wiki/` 문서에는 핵심 주장과 근거 위치를 함께 남긴다.
- 근거가 부족한 내용은 `확인 필요`로 표시한다.
- 서로 충돌하는 자료가 있으면 하나로 합치지 말고 충돌 사실을 적는다.
- 오래된 정보일 수 있는 내용에는 확인 날짜를 남긴다.

### `wiki/`에 담지 않는 것

- 측정을 어떤 순서로 돌렸는지, 중간 실행이 어떻게 실패했는지의 과정은 담지 않는다. `raw/` 세션 로그에 두고 링크한다.
- 리뷰 라운드별로 무엇을 지적받아 어떻게 고쳤는지의 경위는 담지 않는다. 반영된 결과만 담는다.
- 접은 대안의 검토 과정은 담지 않는다. 무엇을 하지 않기로 했고 그 이유가 무엇인지만 한 항목으로 남긴다.
- 이 셋을 담기 시작하면 한 문서가 결론과 경위를 같이 지게 되어 읽는 사람이 어느 쪽을 읽고 있는지 알 수 없게 된다.

### 소급 적용 범위

- 위 규칙은 2026-08-27 이후 새로 만드는 문서에만 적용한다. 기존 `wiki/` 문서 34개는 쪼개지 않는다.
- 2026-08-25부터 2026-08-26까지는 세션 로그를 남기지 않았고 그 기간의 경위가 `wiki/` 문서 안에 들어가 있다. 그 시기의 운영 방식이므로 그대로 둔다.

## 산출물 작업

- `output/` 문서는 외부 공유를 위한 산출물을 작업하는 공간이다.
- 수정 작업이 발생한 경우 기존 문서를 수정하기보다 새 버전의 문서를 생성한다.
- 근거가 필요한 경우 `wiki/`나 `raw/`의 자료를 링크로 첨부한다.

## 로그 작성

- `log.md`에는 `llm-wiki` 안의 파일을 추가하거나 수정한 이력만 남긴다.
- 심볼릭 링크 설정, 이름 논의처럼 `llm-wiki` 파일 변경이 없는 작업은 남기지 않는다.
- `날짜 | 작업 | 결과 | 확인 필요` 표 형식을 유지한다.
- 완벽한 감사 기록일 필요는 없다. 나중에 다시 확인할 수 있을 정도로만 남긴다.
- 판단과 처리의 흔적을 지우지 않는다. 되돌릴 내용이 있으면 기존 줄을 지우지 말고 새 줄로 추가한다.

## 노션 기능 정의서 작성 톤

- 기능 정의서는 프로젝트 owner뿐 아니라 다른 사람들이 읽고 논의하기 위한 문서이다. 세션에서 논의한 내용을 가공 없이 그대로 옮기지 않는다.
- 반드시 한국어 존댓말로 작성한다. `~입니다`, `~합니다` 형태를 쓰고, 반말이나 미완성 문장을 쓰지 않는다.
- 영어 번역체가 느껴지는 문장을 쓰지 않는다. 한국어로 자연스럽게 읽히는지 검토한다.
- 괄호나 대시로 문장에 부연 설명을 덧붙이지 않는다. 설명할 내용이 많으면 문장을 짧게 나눠 쓴다.

## 답변 원칙

- 위키에 근거가 있는 내용과 추정을 구분한다.
- 사용자가 보고서나 실행 계획을 요청하면 관련 `wiki/` 문서를 먼저 확인한다.
- 민감 정보가 포함된 자료는 외부 전송이나 웹 검색에 사용하지 않는다.
- 문서를 작성할 때에는 반드시 완성된 문장으로 작성한다. '~임, ~함' 등 명사형 종결 어미를 쓰지 않는다.
