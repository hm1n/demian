# 사전 인터뷰 - 인터뷰이 1

## 인터뷰 목적

개발 교육생이 프로젝트 경험을 정리하거나 면접을 준비할 때, 자신이 해결한 문제와 기술적 판단을 발견하고 설명하는 데 실제로 어려움을 겪는지 확인한다. 인터뷰에서는 먼저 제품 아이디어를 설명하지 않고, 응답자가 스스로 겪었던 경험과 어려움을 말하도록 유도한다.

## 인터뷰 내용

1. 최근 프로젝트를 이력서나 포트폴리오에 정리해본 적이 있나요? 있었다면 어떤 과정이 가장 어려웠나요?
네. 이 프로젝트를 어떻게 하면 내가 원하는 방향대로 잘 보여줄 수 있을지가 가장 큰 고민이었다.

2. 지금 최근 프로젝트에서 본인이 해결했던 기술적인 문제 하나를 떠올려서 설명해주실 수 있나요?
클로드 코드로 웹 스크래핑을 했는데 클로드 코드가 윤리적인 문제에 위배된다고 거절했다. 이렇게 거절할 수도 있구나 라는 생각이 들었고 직접 코드를 짜서 스크래핑을 돌렸다. 이 때 playwright를 활용했던 게 기억에 남는다.

3. 프로젝트 경험을 정리하거나 다시 떠올릴 때 주로 무엇을 참고하나요? 예: 기억, GitHub, PR, Notion, 팀원 등
기존에 작성했던 노션 일지를 참고한다. 노션에 기록하는 이유는 동기화 때문이고, 노션이 아니라면 옵시디언에 기록했던 일지를 참고한다. 일지에는 기존에 어떤 작업을 했고, 프로젝트 단위로 들어간다면 내가 어떤 질문을 했고 AI가 어떤 답변을 했는지, 이 과정에서 어떤 의사결정을 했는지를 주로 적는다.
경험을 정리할 때 일지 문서들을 뒤져서 경험을 정리하는데, 이렇게 꺼내서 정리하는 게 너무 힘들고 어렵다. 그래서 STAR 기법으로 직접 필기를 하거나 타이핑을 해서 정리하고 있다. 경험을 직접 정리하는 과정이 필요한 것 같다.

4. 예전에 작성한 코드를 다시 봤을 때 "왜 이렇게 구현했지?" 또는 당시의 선택 이유가 잘 기억나지 않았던 경험이 있나요?
아쉬웠던 건 1년차 때 파일 업로드 기능을 구현했는데, 파일을 업로드하면 제대로 업로드되지 않았던 현상이 있었다. 다른 게 원인이라고 판단해서 작업하고 있었는데 다른 개발자 분이 원인을 짚어주셨다. 그것 덕분에 해결이 돼서 '이렇게도 생각할 수 있구나'하는 깨달음을 얻었었는데 … 이 트러블슈팅 경험이 잘 기억이 안 나서 아쉽다. 그래서 이 경험이 정리가 잘 되어 있었더라면 좋았을 것 같다.

5. 프로젝트를 이력서나 포트폴리오에 작성할 때 어떤 경험을 강조해야 할지 판단하기 어려웠던 적이 있나요? 있었다면 어떤 점이 어려웠나요?
많다. ADR 작성도 이번에 알게 되어 (그동안 작성하지 못했던 점이) 아쉬웠다. 이런 것들을 놓치며 살았구나 싶어 아쉬웠다.

6. 면접에서 본인의 프로젝트나 코드에 대해 질문받는다면 어떤 부분을 설명하는 것이 가장 어렵거나 걱정되나요?
AI가 쓴 부분을 내가 직접 의도를 설명하는 게 어려울 것 같다. 직접 손으로 쓸 때까지만 해도 왜 그렇게 했는지 기억이 다 났는데, 지금은 다 AI가 쓰니까 코드를 봐도 의도를 모르겠다거나 판단에 대한 기억이 잘 남지 않는 경험이 많다.

7. 내 GitHub Repository를 분석해서 내가 놓치고 있던 개발 경험을 찾아주고, 실제 코드를 기반으로 질문을 던져 그 경험을 설명하는 연습까지 할 수 있다면 사용해보고 싶으신가요?
