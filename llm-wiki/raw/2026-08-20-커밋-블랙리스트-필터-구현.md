# 커밋 블랙리스트 필터 구현 기록

## 근거

- GitHub Issue #2 `커밋 메타데이터 기반 블랙리스트 필터 구현`
- Notion 기능 정의서 `Repository 데이터 조회 및 분석`

## 구현 결정

- 전체 커밋 조회 결과에 원문 커밋 메시지와 부모 커밋 수를 보존합니다.
- 분류 로직은 변경 파일 정보를 받지 않고 커밋 메시지와 부모 커밋 수만 받습니다.
- 여러 규칙이 겹치면 병합, 문서, 의존성, 오타, 포맷팅 순서에서 처음 일치한 카테고리만 반환합니다.
- 전체 커밋 조회 결과는 유지하고, 별도의 `filterCommitsForDetail` 함수가 블랙리스트에 해당하지 않는 커밋만 반환합니다. 아직 상세 조회 기능이 구현되지 않았으므로 이 함수가 두 번째 단계와의 연결 경계입니다.

## 검증

- 5개 카테고리의 키워드와 접두사 및 패턴을 테스트했습니다.
- 카테고리가 겹치는 메시지의 판별 우선순위를 테스트했습니다.
- 원문 메시지 본문의 키워드도 판별하는지 테스트했습니다.
- 전체 테스트 51개와 lint 및 typecheck가 통과했습니다.

## 확인 필요

- 블랙리스트 키워드는 실제 커밋 데이터로 검증한 뒤 조정해야 합니다.
- 상세 조회 기능을 구현할 때 `filterCommitsForDetail` 결과만 API 호출 대상으로 사용하는 통합 테스트가 필요합니다.
