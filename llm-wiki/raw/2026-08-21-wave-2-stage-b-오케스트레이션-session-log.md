### 브리프 단계에서 닫은 이슈 본문의 확인 필요 항목

- Gemini 모델과 env 변수: 설치된 `@ai-sdk/google@4.0.45`가 지원하는 모델 id 목록을 직접 확인해
  `gemini-3.7-flash`로 고정했다. env 변수는 provider 기본값 `GOOGLE_GENERATIVE_AI_API_KEY`를
  쓰므로 env를 직접 읽는 코드를 추가하지 않았다.
- 실행 상한 초과 대응: 이슈 본문이 "임의로 선택하지 않는다"고 명시한 항목이다. **후보 축소
  재시도와 요청 2개 분할 중 어느 쪽도 채택하지 않았다.** 요청 분할은 "한 번의 판단" 확정과
  충돌해 기각 상태를 유지했고, 서버 내부 축소 재시도는 첫 시도가 예산을 이미 소진한 상태여서
  같은 함수 실행 안에서는 성립하지 않는다. 대신 입력을 결정론적으로 제한하고 초과 시
  `llm_timeout` 504로 끝낸다. 축소 재시도가 성립하는 형태는 클라이언트가 더 적은 후보로 다시
  요청하는 것이며 이슈 #18 계층이다.
- `fileTree`를 입력으로 받지 않기로 했다. 모델이 프롬프트에서 보지 못한 경로는 인용할 수 없어
  검증만 느슨해지고 본문만 커진다. 서버가 직접 조회하면 가장 지연에 민감한 엔드포인트에 API
  호출 2회가 늘어난다.

### 리뷰에서 바뀐 설계

- **라우트 전체 시간 예산.** 최초 구현은 55초 타이머를 GitHub 조회 루프 뒤에 시작해서, 조회가
  쓴 시간이 예산에서 빠져 있었다. 후보 20개면 순차 요청 40회다. `maxDuration = 60`보다 먼저
  오류를 반환한다는 계약이 깨져 있었다. 원인은 브리프가 Stage A의 시한 상수 의미를 그대로
  지시한 것이다. Stage A는 LLM 호출 전에 하는 일이 없지만 Stage B는 다르다.
- **`source` 불일치를 전체 거부에서 서버 교정으로 변경.** 근거는 계약 문서의
  `## source 값의 권위` 절에 있다. 일반 기준은 **서버가 정답을 확정적으로 아는 필드는 교정하고,
  환각 SHA처럼 모델 의도를 알 수 없는 필드는 전체 거부한다**는 구분이다.
- **후보 SHA 형식 검증.** `isCandidate`가 빈 문자열만 아니면 통과시켜서, 클라이언트가 브랜치명을
  보낼 수 있었다. `AGENTS.md`의 "이동 가능한 ref를 커서로 쓰지 않는다" 규칙 위반이라 P2였지만
  backlog로 미루지 않고 반영했다.

## 남은 backlog

- `handleStageB`의 3번째 파라미터 이름이 `timeoutMs`인데 의미는 라우트 전체 예산이다. 이름이

## 이슈 #18이 이어받을 확인 필요 항목

이번 웨이브에서 늘어난 것을 포함한다.

- `llm_timeout`이 Stage B에서는 GitHub 조회를 포함한 **전체 예산 소진**을 뜻한다. LLM 자체 실패와
  구분해 사용자에게 보여줄지 정해야 한다.
- 예산 초과 시 후보 수를 줄여 다시 요청하는 흐름을 클라이언트가 담당할지. 서버는 하지 않는
  것으로 확정됐다.
- LLM 단계만 재시도 가능한지, 아니면 GitHub 조회부터 다시 하는지.
- 후보가 3개 미만일 때 기준을 낮추지 않는다는 정책을 화면에서 어떻게 표현할지.

이슈 #18이 완료되면 `/api/candidates/stage-a`와 `/api/candidates/stage-b`에 프로덕션 호출자가
없다는 알려진 한계 2건이 함께 해소된다.
