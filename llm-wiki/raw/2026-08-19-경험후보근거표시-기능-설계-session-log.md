# 경험 후보별 Repository 근거 표시 기능 설계 세션 로그

## 문서 목적

"경험 후보별 Repository 근거 표시" 기능을 설계하면서 논의하고 결정한 내용을 보존한다.

## 논의 내용

### 확인 불가 판단을 누가 하는가

`llm-wiki/output/2026-08-19-서비스기획-확정-v1.md`와 원본 기획안에서는 "Repository만으로 확인할 수 없는 사실은 명확히 구분해서 보여준다"는 원칙만 있었고, 이 판단을 어느 기능이 담당하는지는 정해져 있지 않았다. "개발 경험 후보 생성"이 후보를 만들 때 미리 태깅하는 안과, "경험 후보별 Repository 근거 표시"가 판단하는 안을 비교했다. 근거 표시 기능이 판단하는 것으로 결정했다. 점수 계산과 순위 매기기라는 후보 생성의 역할과, 근거를 사용자에게 설명 가능한 형태로 가공하는 역할을 분리하기 위함이다.

### 사용자 흐름 구조

후보 3개의 모든 근거를 한 화면에 다 펼쳐서 보여주는 안과, 리스트에서 요약만 보여주고 상세 화면으로 진입하는 안을 비교했다. 리스트에서 요약을 보여주고 클릭하면 상세로 진입하는 구조로 결정했다. 화면이 길어지고 정보가 많아지는 문제를 피하기 위함이다.

### "경험 후보별 Repository 근거 표시"와 "경험 선택"의 경계

두 기능이 이어지는 흐름이라 경계가 모호해질 수 있다는 점을 미리 짚었다. 근거 표시 기능은 리스트와 상세 화면을 보여주는 것까지 담당하고, 사용자가 실제로 하나의 경험을 선택하는 액션 처리와 다음 단계로 전달하는 일은 "경험 선택" 기능이 담당하는 것으로 정했다.

### 확인 불가 판단 규칙

구체적인 자동 판별 알고리즘을 지금 확정하기는 이르다고 판단해, 일반 원칙만 정하고 세부 규칙은 구현 단계로 유보했다. 원칙은 다음과 같다. 커밋 메시지나 diff에 구체적인 수치, 비교, 의도가 명시되지 않은 항목은 확인 불가로 표시한다. 예를 들어 성능 개선 폭, 사용자 영향, 다른 대안과의 비교, 협업이나 논의 배경 같은 항목이 여기에 해당한다.

## 결정 사항 요약

- "Repository만으로 확인할 수 없는 사실"을 구분하는 판단은 "경험 후보별 Repository 근거 표시" 기능이 담당한다. "개발 경험 후보 생성"은 점수 계산과 순위 매기기까지만 담당한다.
- 사용자 흐름은 후보 3개를 리스트로 요약해 보여주고, 클릭하면 상세 근거 화면으로 진입하는 구조로 한다.
- 이 기능은 근거를 보여주는 것까지 담당하고, 사용자가 경험을 선택하는 액션은 "경험 선택" 기능이 담당한다.
- 확인 불가 판단은 커밋 메시지나 diff에 구체적인 수치, 비교, 의도가 명시되지 않은 항목을 확인 불가로 표시한다는 일반 원칙만 정하고, 세부 규칙은 구현 단계에서 정한다.
