## 인터뷰 내용

1. 개발 경험을 AI가 질문하면서 되짚어보고, 본인이 왜 그렇게 구현했는지 설명할 수 있도록 돕는 흐름이 실제 학습 효과가 있을 것으로 보이시나요?

정리하는 것 자체에는 많이 도움이 되겠지만 설명할 수 있으려면 닭과 달걀의 문제인 것 같다. 내가 알고 프롬프트를 치면 설명할 수 있는데, 내가 모르고 해줘! 하고 지시하면 결국 모르는 게 되어 버린다. 프롬프트를 의도를 갖고 치는 사람한테는 도움이 되겠지만 그냥 해줘 하는 사람에게는 크게 의미가 없을 것 같다.

코드 리뷰 결과를 기반으로 면접 때 이런 걸 준비해보라고 제안해준다거나 하는 것도 좋을 것 같다. 바이브 코딩으로 구현한 사람에게도 코드의 의도에 대해 질문하는 방식이라면 좋을 것 같다.

2. 교육생들을 보시면서 "내가 한 것 중에 어떤 경험을 정리해야 할지 모르겠다"거나, "구현은 했는데 당시 왜 그렇게 결정했는지 잘 기억이 안 난다"고 어려워하는 경우가 실제로 자주 있었나요?

많다. 부트캠프도 보통 3~4개월 진행하기 때문에 정리를 어려워하는 경우가 많다.

정리하지 못하는 사람은 수치화를 잘 못 한다. 내가 뭘 얼마나 개선했는지를 잘 뽑아내지 못해서 그런 부분에서 피드백을 많이 준다. 잘 하는 교육생들은 수치화도 알아서 잘 한다.

3. AI가 작성한 코드나 바이브 코딩으로 만든 결과물을 본인이 제대로 이해하거나 설명하지 못하는 경우도 자주 보셨나요?

3-1. 이런 문제도 AI가 계속 질문하면서 스스로 설명하게 만드는 방식으로 어느 정도 해결할 수 있을까요?

적정 수준이면 도움이 되겠지만 개발을 아예 접해보지 않은 사람, 바이브 코딩을 아예 접해보지 않은 사람들에게는 크게 도움이 되지 않을 것 같다.

4. "왜 이 기술을 선택했나요?", "다른 방법은 고려하지 않았나요?"처럼 계속 꼬리 질문을 하는 방식이 실제 교육생들이 면접이나 발표를 준비할 때 도움이 될까요?

도움은 된다. 실제 면접 질문들이 보통 기술의 결정 이유를 물어보기 때문에 그걸 의식적으로 물어본다면 도움이 될 것 같다.
