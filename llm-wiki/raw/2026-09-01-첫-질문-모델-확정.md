# 첫 질문 생성 모델 확정

## 확정

**첫 질문 생성은 `gemini-3.1-flash-lite`로 확정한다. 2순위는 `gemini-3.5-flash-lite`다.**

**질문을 코드 수준으로 좁혀야 할 경우 모델을 바꾸지 않고 프롬프트를 고도화해 푼다.**

## 확정 근거

### 1. 질문의 성격이 이 경로의 목적에 맞는다 (사람 판단)

두 모델을 같은 근거로 10회·9회 돌려 질문 원문을 비교한 결과 성격이 갈렸다.

- `gemini-3.1-flash-lite`는 **여러 파일을 엮어 설계 전체의 의도를 묻는다.** 측정 하네스가 어떤 구현
  결정을 이끌었는지, 어떤 제약을 만들었는지를 묻는다.
- `gemini-3.5-flash-lite`는 **한 지점을 인용하고 그 지점만 좁게 묻는다.** 주석 한 문장, 표현식 하나,
  함수 하나를 집어 온다.

`AGENTS.md`의 원칙은 사용자가 자기 경험을 스스로 설명하도록 잣대를 주는 것이다. **범용적으로 설계
의도를 묻는 쪽이 그 목적에 맞다는 것이 사람의 판단이다.** 지표로 환산되지 않는 축이고, 이 확정에서
유일하게 수치가 아닌 근거다.

### 2. 좁은 질문이 필요하면 프롬프트로 푼다

코드 수준으로 좁힌 질문이 필요하다고 판명되면 모델을 `gemini-3.5-flash-lite`로 바꾸는 것이 아니라
**시스템 프롬프트를 고도화한다.** 근거는 두 가지다.

- 이 프로젝트는 프롬프트 문구가 모델 행동을 바꾼다는 실측을 이미 갖고 있다. 같은 지시를 한 문단에
  두느냐 갈라 두느냐로 Stage A 전수 응답률이 0/3에서 3/4로 바뀌었다
  (`wiki/2026-08-25-Stage-A-청크-폐기와-점수-선별-전환.md`). `question-prompt.ts`가 그래서 변형 두 개를
  들고 있다.
- 모델을 바꾸면 지연·단가·계약 준수를 다시 다 재야 하지만, 프롬프트는 같은 모델에서 변형 비교만
  하면 된다. 되돌리기도 쉽다.

### 3. 수치 축에서는 두 모델이 갈리지 않는다

| 축 | `gemini-3.1-flash-lite` | `gemini-3.5-flash-lite` |
| --- | --- | --- |
| 첫 청크 (상한 5,250) | 1,172~1,581ms | 1,165~1,200ms |
| 첫 청크 (상한 3,500) | 1,037~1,172ms | 1,196~1,398ms |
| 시한 20초 대비 | 6~8% | 6~7% |
| 인용 검증 위반 | 0건 | 0건 |
| 질문 개수 규칙 | 준수 | 준수 |
| 회차 | 10회 | 9회 |

구간이 겹친다. **지연으로는 가릴 수 없다.**

### 4. 단가가 더 싸다

| 모델 | 입력 | 출력 | 첫 질문 회당(입력 5,043 / 출력 약 200) |
| --- | --- | --- | --- |
| **`gemini-3.1-flash-lite`** | **0.25** | **1.50** | **0.00157달러** |
| `gemini-3.5-flash-lite` | 0.30 | 2.50 | 0.00196달러 |

두 모델 모두 인상 예정이 없다. 단가 출처는 `raw/2026-08-27-모델-단가-데이터조항-확인.md` 87~88행이다.

### 5. 상한 의존이 없다

`gemini-3.5-flash-lite`는 근거 상한 3,500에서 두 회차 모두 커밋 메시지 수준 질문을 냈고 5,250에서만
코드를 짚었다. `gemini-3.1-flash-lite`는 **두 상한 모두에서 코드 파일을 짚었다.** 상한을 나중에 다시
내려야 하는 상황이 와도 질문 품질이 무너지지 않는다.

또한 3,500에서 `gemini-3.5-flash-lite`가 `측정 스크라이브러리`라는 없는 낱말과 끊긴 문장을 냈다.
사용자에게 그대로 보이는 자리다. 5,250 세 회차에서는 재발하지 않았으나 관측 자체는 남는다.

## 이 확정이 남긴 조건

1. **배선하지 않았다.** `question-generation.ts:29`의 `INTERVIEW_QUESTION_MODEL`이 여전히
   `openai/gpt-oss-20b`이고 provider도 `createGroq()`다. Gemini로 옮기려면 provider 배선도 함께
   바꿔야 한다.
2. **유료 등급 전환이 선행 조건이다.** 무료 등급은 입력을 학습에 쓰므로 교육생 코드를 보낼 수 없다.
   Stage A·B와 같은 조건이다.
3. **Stage A와 같은 모델을 쓰게 된다.** 한도가 모델별이므로 두 경로가 한 통을 공유한다. 인터뷰
   한 번에 각각 1회씩이라 지금은 문제가 없으나, **꼬리 질문은 반드시 다른 모델에 둔다.** 가장 자주
   부르는 경로가 앞 단계의 할당량을 먹으면 안 된다.
4. **Gemini 유료 등급의 한도가 모델별인지 확인하지 않았다.** 3번 규칙이 여기에 걸린다.
5. **프롬프트 고도화의 판단 기준이 없다.** 좁은 질문이 필요한지 아닌지는 사용자가 실제 인터뷰를
   해 봐야 갈린다.
