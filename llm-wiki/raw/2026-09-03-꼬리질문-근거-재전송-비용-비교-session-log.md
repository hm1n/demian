# 꼬리 질문의 근거 재전송 설계 비용 비교

## 왜 쟀는가

`wiki/2026-09-01-네-경로-LLM-모델-확정.md` 3-4절이 "근거를 매 턴 다시 실을지가 아직 설계 결정으로
열려 있다"고 남겼고, 8절 4번이 같은 항목을 남은 조건으로 들고 있습니다. 그때의 비용 표는 입력
50,000토큰을 가정한 환산이었습니다. 이 문서는 그 가정을 실측 토큰으로 바꿉니다.

## 어떻게 쟀는가

Gemini `countTokens`로 셌습니다. **생성을 호출하지 않으므로 요금과 일일 요청 쿼터를 쓰지
않았습니다.** 프롬프트는 운영 코드(`renderInterviewQuestionSystemPrompt`,
`renderInterviewEvidencePrompt`)를 그대로 접었고, 근거 스냅샷은 실제 GitHub 응답으로
`buildExperienceEvidenceSnapshot`이 만들었습니다.

측정이 자신의 정확성을 확인한 지점이 하나 있습니다. PR #61 근거의 첫 질문 입력이 **5,043토큰**으로
나왔고, 이 값은 `wiki/2026-09-02-LLM-비용-산정.md` 3절의 첫 질문 실측 입력 5,043토큰과 같습니다.
같은 프롬프트를 다른 경로(생성 usage와 countTokens)로 잰 값이 일치합니다.

### 가정으로 남긴 값

- **사용자 답변 길이.** 실제 사용자 답변이 없습니다. 200자(96토큰), 600자(291토큰),
  1,500자(734토큰) 세 구간으로 나눠 각각의 결과를 냅니다.
- **꼬리 질문 출력 길이.** 매 턴 200토큰으로 뒀습니다. 첫 질문 실측 178~213토큰의 위쪽입니다.
- **대화 이력에 실리는 질문 본문.** 측정에 쓴 표본이 152토큰으로 첫 질문 실측보다 26~61토큰
  짧습니다. 턴마다 그만큼 과소평가되며 10턴 기준 최대 약 550토큰, 회당 0.00014달러입니다.
- **캐시 유지 시간.** 설계 C의 스토리지 몫을 재려고 0.5시간으로 뒀습니다. 이 값의 영향은 4절에서
  분리했습니다.

## 1. 비교한 설계

API가 상태를 갖지 않으므로 "대화를 잇는다"는 것은 매 호출에 이력을 다시 싣는다는 뜻입니다. 근거도
이력 안에 남겨 두면 매 턴 다시 실립니다.

| 설계 | 매 턴 프롬프트 | 근거 원칙 |
| --- | --- | --- |
| A | 시스템 + 근거 전량 + 대화 전문 | 지킵니다 |
| B | 시스템 + 대화 전문. 근거는 첫 턴에만 | 근거 본문이 사라집니다 |
| C | A와 같은 입력. 시스템+근거 접두사를 캐시 단가로 | 지킵니다 |
| D | 시스템 + patch를 뺀 축약 근거 + 대화 전문 | patch 본문이 사라집니다 |

## 4. 캐싱의 손익분기는 시간으로 정해집니다

설계 C의 이득은 캐시를 얼마나 오래 붙들고 있는지에 달려 있습니다. 접두사를 캐시 단가로 내리는
절감은 `턴 수 × 접두사 토큰 × (0.25 - 0.025) / 1,000,000`이고 스토리지 요금은
`접두사 토큰 × 1.00 × 시간 / 1,000,000`입니다. 접두사 토큰이 양쪽에 같이 들어가 약분되므로
**손익분기는 근거 크기와 무관하게 `0.225 × 꼬리 질문 횟수` 시간입니다.**

| 꼬리 질문 횟수 | 손익분기 |
| --- | --- |
| 5회 | 1.1시간 |
| 9회 (10턴) | 2.0시간 |
| 14회 (15턴) | 3.2시간 |

측정에서 세 답변 길이 모두 2.025시간으로 같게 나와 이 유도를 확인했습니다. 인터뷰 하나가 두 시간
안에 끝나면 캐싱이 이득이고, 사용자가 창을 열어 둔 채 자리를 비우면 손해로 뒤집힙니다.

**확인하지 못한 것이 둘 있습니다.** 명시적 캐싱의 최소 토큰 조건을 이번에 문서로 확인하지
않았습니다. 접두사가 5,043토큰이라 통과할 것으로 보지만 확인 전입니다. 암묵적 캐싱이 이 모델에
자동으로 걸리는지도 확인하지 않았습니다. 걸린다면 스토리지 요금 없이 같은 절감이 생기므로 C의
전제가 달라집니다.

## 5. 측정이 함께 드러낸 것

**요청 본문 상한 64KB가 꼬리 질문에서 먼저 깨집니다.** `MAX_INTERVIEW_STREAM_BODY_BYTES`는 근거
스냅샷 하나를 기준으로 정한 값입니다. 클라이언트가 대화 전문을 매 턴 실어 보내면 1,500자 답변
기준 10턴에서 본문이 58KB 근처가 되고 15턴에서 상한을 넘깁니다. 대화를 서버가 들고 있지 않는 한
이 상한은 꼬리 질문 기준으로 다시 정해야 합니다.

**비용 차이는 전부 입력 쪽입니다.** 출력은 설계와 무관하게 매 턴 같은 200토큰입니다. 따라서 설계
선택은 품질 대 입력 토큰의 교환이고, 이 문서가 재는 것은 그중 토큰 쪽뿐입니다.

## 6. 이 측정이 답하지 못하는 것

설계 B와 D의 질문 품질입니다. B는 근거 본문 없이 대화만 보고 질문을 만들므로 근거에 없는 파일과
수치를 지어낼 여지가 생깁니다. 그것은 서비스의 전제(`AGENTS.md`: AI는 항상 실제 Repository의
커밋과 파일을 근거로 제시한다)를 직접 건드립니다. D는 patch 없이 커밋 제목과 파일 목록만으로
질문을 만들 때 커밋 메시지 수준의 질문으로 내려앉는지가 확인되지 않았습니다.

비용만 보면 B가 가장 싸지만 비용은 이 선택의 종속 변수가 아닙니다. 품질 비교는 생성 호출이 필요한
별도 측정입니다.
