# 첫 질문 생성 모델 실측 (Gemini 3종 + DeepInfra 2종 + Groq 기준선)

## 문서 목적

Stage A·B를 Gemini로 확정한 뒤 남은 경로다. 이 경로는 `streamText`로 자유 텍스트를 흘리므로 기준이 총
지연이 아니라 **첫 청크 지연**(시한 20초)이다. 2026-08-25 측정은 Groq `gpt-oss-20b`와 `gemini-3.6-flash`
둘만 비교했고 Lite 계열과 DeepInfra는 후보에 없었다. 이번에 여섯 경로를 같은 스냅샷으로 쟀다.

## 측정 방법

- 프로덕션 코드(`buildInterviewQuestionPrompt`, `startInterviewQuestionStream`)를 그대로 쓰는 계측
  스크립트다. 프롬프트를 손으로 다시 조립하지 않았다.
- 대상은 본인 저장소 `hm1n/demian`이다. 무료 등급 Gemini에 교육생 코드를 보내지 않았다.
- 프롬프트 변형은 프로덕션과 같은 `split` 하나만 썼다. 모델당 2회(PR 2건)다.
- 입력 두 건을 **patch 몫이 극단으로 다른 PR로 골랐다.**
  - PR #61: 커밋 6개, 직렬화 10,376바이트, metadataTokens 3,444, **patch 144/168바이트**(거의 굶음)
  - PR #51: 커밋 2개, 직렬화 10,436바이트, metadataTokens 1,891, **patch 4,814/4,827바이트**(풍부)
- 첫 청크 시한 20,000ms, 총 시한 55,000ms는 프로덕션 값 그대로다.
- 로그에는 수치와 질문 원문만 남겼다.

### 계측 스크립트를 고쳤다

`question-generation.measure.mts`에 provider `deepinfra`와 `--provider=` 필터, `--skip-deepinfra`를
넣고 Gemini 후보에 Lite 두 모델을 추가했다. **DeepInfra는 새 의존성 없이 `createGroq({ baseURL })`로
붙였다.** `llm-provider.ts`의 `requireLocalModel`이 이미 쓰는 방식이므로 여기서 잰 배선 비용이 실제
전환 비용과 같다.

### PR #56은 더 이상 입력으로 못 쓴다

2026-08-25 측정이 쓴 PR #56과 #67, #57은 이제 `evidence_input_too_large`로 스냅샷 조립이 실패한다.
프롬프트 상한 14,000바이트를 넘는다. 그래서 입력을 #61과 #51로 갈았다. **2026-08-25 표와 절대값을
직접 비교할 수 없는 이유다.** 같은 표 안의 여섯 경로끼리는 같은 입력이므로 비교된다.

## 판정 1. Lite 계열이 Groq와 같은 구간에 들어왔다

첫 청크가 `gemini-3.5-flash-lite` 1,074~1,481ms, `gemini-3.1-flash-lite` 1,172~2,570ms, Groq
`gpt-oss-20b` 1,524~1,862ms다. **세 경로가 같은 구간이고 3.5-lite가 그중 가장 빠르다.**

2026-08-25 결론인 "Groq가 첫 청크까지 1.5~2.5초, Gemini가 8.1~9.5초로 4~5배 차이"는 **Gemini 쪽 대상이
`gemini-3.6-flash` 하나였기 때문에 나온 값이다.** 이번에 3.6-flash는 7,727~8,885ms로 그때와 같게
나왔으므로 그 관측 자체는 재현됐다. 달라진 것은 Gemini에 더 빠른 모델이 있다는 사실이다.
**따라서 "첫 질문은 지연 때문에 Groq여야 한다"는 근거가 사라졌다.**

## 판정 2. DeepInfra는 이 경로에서 시한을 위협한다

`gpt-oss-120b`가 PR #51에서 첫 청크 **19,382ms**다. 시한 20,000ms까지 여유가 **618ms**다. 같은 모델
PR #61이 13,165ms이므로 회차 분산만으로도 넘는다. **운영에 올리면 `llm_timeout`이 간헐로 난다.**
`gpt-oss-20b`도 5,919~8,580ms로 Groq의 같은 모델보다 3.2~5.6배 느리다.

Stage A 실데이터에서 얻은 결론(같은 모델을 Groq가 4.6배 빠르게 서빙한다)이 스트리밍에서도 재현됐다.
**`gpt-oss` 계열의 지연은 모델 특성이 아니라 서빙 차이다.** 이 경로에서 DeepInfra는 탈락이다.

## 판정 3. DeepInfra는 토큰 사용량을 보고하지 않는다

`@ai-sdk/groq`를 baseURL만 갈아 붙였을 때 `usage.inputTokens`와 `usage.outputTokens`가 모두 null이다.
`x-ratelimit-*` 헤더도 없다(2026-08-28 raw 기록과 같다). 즉 이 provider로 가면 **토큰 회계와 한도
백오프 배선을 새로 써야 한다.** Groq는 같은 호출에서 여섯 개 헤더를 다 준다.

```
x-ratelimit-limit-tokens 8000 / x-ratelimit-remaining-tokens 5296 / x-ratelimit-reset-tokens 20.28s
```

## 판정 4. 사고 토큰이 출력 단가로 과금된다

`gemini-3.6-flash`는 출력 문자 643자에 **출력 토큰 1,554개**를 썼다. `gemini-3.5-flash-lite`는 437자에
193개다. 문자당 출력 토큰이 **8배**다. 차이는 사고 토큰이고 출력 단가로 과금된다.

| 모델 | 회당 비용(PR #61 실측 토큰) |
| --- | --- |
| `gemini-3.1-flash-lite` | 0.00106달러 |
| `gemini-3.5-flash-lite` | 0.00134달러 |

3.6-flash가 3.5-lite의 **6배**다. 꼬리 질문·채팅이 같은 모델을 쓰고 대화가 이어지면 이 배수가 그대로
곱해진다.

## 판정 5. 규칙 위반과 만들어낸 사실이 provider별로 갈린다

시스템 프롬프트 규칙은 질문 정확히 1개, 근거에 있는 것만 인용, 확인 불가 항목을 사실로 단정하지 않기,
한국어 Markdown 4문장 이내다.

| 경로 | 위반·결함 |
| --- | --- |
| `gemini-3.5-flash-lite` | 없다. 질문 1개, 308~437자로 가장 짧다 |
| `gemini-3.1-flash-lite` | 없다. PR #51에서 `secondary rate limit`을 언급했는데 스냅샷 슬라이스 포함 여부는 확인 못 했다(아래 한계) |
| `gemini-3.6-flash` | 없다. 598~643자로 가장 길고 커밋 두 개의 전후 관계를 짚었다 |
| groq `gpt-oss-20b` | PR #61 말미에 **`이 질문은 4문장 이내로 구성했습니다.`** 라는 메타 문장을 붙였다. PR #51은 출력 976자에 diff 블록을 인용문으로 통째로 싣고 `이상.`으로 끝냈다. **4문장 규칙 위반이다** |

| deepinfra `gpt-oss-120b` | 질문 본문 끝에 시스템 프롬프트 규칙을 **되풀이했다**(`※ 답변에서는 ... 추정하지 말고 ... 명시해 주세요`). 사용자에게 갈 질문에 모델용 지시가 섞였다 |

2026-08-25에 Groq `gpt-oss-20b`에서 관측한 "근거에 없는 사실을 만든다"가 **같은 모델의 다른 제공자에서
재현됐다.** 모델 특성이다. **Gemini 세 모델은 세 경로 모두 만들어낸 사실이 없었다.**

## 판정 6. patch가 굶으면 질문이 커밋 메시지 기반으로 밀린다

PR #61은 patch 몫이 144바이트다. 여섯 경로 전부 커밋 메시지와 파일 경로만으로 질문을 만들었고, 코드
내용을 묻는 질문이 하나도 없었다. PR #51은 patch 4,814바이트이고 `STAGE_A_TOKEN_RESERVE`,
`STAGE_A_CHUNK_MAX_FILES`, `concurrency` 같은 실제 식별자를 짚은 질문이 나왔다.
**2026-08-25 backlog의 "관련 커밋이 6개면 patch 몫이 168바이트로 줄어 코드 기반 질문이 커밋 메시지
기반 질문이 된다"가 실측으로 재확인됐다.** 모델 선정으로 해결되지 않는 항목이다.

## 이 측정의 한계

1. **스냅샷 원문을 확인하지 않았다.** 계측 스크립트가 프롬프트 본문을 출력하지 않는다. 따라서 모델이
   짚은 식별자가 **patch 슬라이스 안에 있었는지** 확인할 수 없다. PR #51 전체 diff에는
   `STAGE_A_TOKEN_RESERVE` 7건, `6,000` 6건, `secondary` 1건이 있으므로 저장소 사실로는 맞다. 그러나
   입력에 없었다면 만들어낸 사실이다. **판정 5의 Gemini "위반 없음"은 이 한계 위의 값이다.**
2. **모델당 2회다.** Lite 계열의 배치 분산이 작았으나 스트리밍 첫 청크의 분산은 확인하지 않았다.
3. **무료 등급 Gemini 값이다.** 유료 전환 후 지연이 달라질 수 있다.
4. **질문 품질의 정답이 없다.** 어느 질문이 인터뷰로 더 쓸 만한지는 사람이 읽어야 갈린다.
5. **꼬리 질문·채팅은 재지 않았다.** 대화가 누적되면 입력이 커지고 첫 청크 지연도 달라진다.
6. **`merged` 변형을 재지 않았다.** 프로덕션이 `split`이므로 그것만 쟀다.

## 선정에 미치는 영향

**`gemini-3.5-flash-lite`가 앞선다.** 첫 청크 1,074~1,481ms로 여섯 경로 중 가장 빠르고, 규칙 위반과
만들어낸 사실이 없고, 회당 0.00134달러다. Stage B 확정 모델과 같아 모델 상수도 늘지 않는다.

**2순위는 `gemini-3.6-flash`다.** 2차 투표 최다 득표(3표) 모델이고 질문이 가장 길고 구체적이다. 첫 청크
7.7~8.9초는 시한 20초 안이다. 다만 회당 6배 비용을 사고 토큰에 지불한다. **사람이 질문 품질을 읽고
그 차이가 6배를 정당화한다고 판단하면 뒤집힌다.**

**현재 프로덕션 모델 Groq `openai/gpt-oss-20b`는 교체 대상이다.** 지연은 여전히 최상위권이지만 4문장
규칙을 어기고 메타 문장을 붙이며, 같은 모델이 다른 제공자에서 만들어낸 사실을 냈다. Groq 유료 전환도
막혀 있다.

# 프롬프트 상한 유도식 전환과 상한 3,500 재측정 (2026-09-01)

## 왜 유도식으로 바꿨나

`INTERVIEW_QUESTION_MAX_PROMPT_BYTES` 14,000은 2026-08-25 실측값이다. 커밋 `76c3d9d`에서 들어왔고
근거가 두 개였다. 관측된 정상 프롬프트 10,446~10,797바이트와 **Groq 무료 등급 분당 8,000토큰**이다.
`14,000바이트는 약 3,840토큰이고 최대 응답 1,678토큰을 더해도 한도의 69%`라는 계산이 주석에 있다.

Gemini로 옮기면 뒤의 못이 빠진다. 앞의 못만으로 새 숫자를 고르면 근거 없는 값이 된다. 20,000을
제안했다가 철회한 이유다.

**대신 근거 상한에서 유도했다.** 예산을 렌더된 프롬프트로 재게 되면서 근거 바이트가 수식으로 묶인다.

```
ceil(근거 바이트 / EVIDENCE_SNAPSHOT_BYTES_PER_TOKEN) <= EVIDENCE_SNAPSHOT_MAX_INPUT_TOKENS
  ⇒ 근거 바이트 <= 상한 × 3
```

| 근거 상한 | 근거 바이트 | + 시스템 1,349 + 2 | 계산된 상한 | 실측 프롬프트 |
| --- | --- | --- | --- | --- |
| 3,500 | 10,500 | 11,851 | 11,851 | 11,687 / 11,715 |
| 5,250 | 15,750 | 17,101 | 17,101 | 16,776 / 16,883 |
| 7,000 | 21,000 | 22,351 | 22,351 | 21,892 / 22,035 |

세 측정 모두 계산 아래다. 시스템 프롬프트는 `split` 1,349바이트, `merged` 1,310바이트이며 둘 중 큰
값을 `INTERVIEW_QUESTION_SYSTEM_PROMPT_MAX_BYTES`로 계산해 둔다. 문구를 고치면 값이 따라 움직인다.

**결과 상수는 12,107바이트다.** 10,500 + 1,349 + 2 + 허용 오차 256이다. 예전 14,000은 계산된 상한보다
18% 높아 근거 상한을 그만큼 넘긴 스냅샷을 통과시켰다. 유도식은 그것을 막는다.

허용 오차 256의 근거는 구성 오차다. patch 몫을 `serializedByteLength`로 세고 완성된 근거를 다시 재지
않으므로 그 차이를 덮는다. 실측 여유가 1.2~1.6%였으므로 쓰일 일이 없어야 하고, 회귀 테스트가 허용
오차 없이도 통과하는 것을 고정한다.

- **입력이 더 큰 PR #51은 네 번 모두 통과했다.** 프롬프트가 11,715바이트로 PR #61의 11,687바이트보다
  크다. 6,564~10,058ms였다.
- **청크가 0개다.** 20초 동안 텍스트가 한 조각도 오지 않았다. 스트리밍이 느린 것이 아니라 **첫 글자가
  나오기 전 단계에서 오래 머문다.**

## 판정 3. 사고 단계가 첫 청크를 막는다 (직접 측정은 못 했다)

`gemini-3.6-flash`는 답을 쓰기 전에 사고한다. 사고는 텍스트 청크로 나오지 않으므로 그 시간이 통째로
첫 청크 지연이 된다. 이 경로에서 출력 토큰이 1,168~1,875인데 화면에 나온 글자는 367~620자다. Lite
모델은 같은 자리에서 127~232토큰이다.

앞선 측정에서 같은 구조를 확인했다(`raw/2026-08-28-Gemini-anyOf-지연-실측.md`). Stage A 크기 입력에서
`gemini-3.6-flash`의 사고가 12,862토큰으로 출력 2,167토큰의 5.9배였고, `thinkingConfig.thinkingBudget: 0`은
400 `Request contains an invalid argument`로 거부됐다. **끌 수 있는 손잡이가 없다.**

다만 이번 경로에서 사고 토큰을 직접 재지는 못했다. 계측에 사고 토큰 수집을 넣었으나
(`usage.reasoningTokens` 없으면 `providerMetadata.google.thoughtsTokenCount`) `@ai-sdk/google`가 이
스트리밍 경로에서 두 값을 모두 주지 않아 `-`로 나온다. **사고가 원인이라는 것은 앞선 네이티브 측정에
기댄 판단이고 이번 실패에서 직접 확인한 값이 아니다.**

## 판정 4. `gemini-3.6-flash`는 이 경로에서 탈락이다

2차 투표 최다 득표(3표) 모델이다. 근거는 세 가지다.

1. 같은 입력에서 첫 청크 시한을 **4회 중 2회** 넘긴다.
2. 성공해도 6.5~13.3초로 분산이 크고, 사고를 끌 수 없어 줄일 수단이 없다.
3. 회당 비용이 Lite의 5~7배다. 사고 토큰이 출력 단가로 과금된다.

`gemini-3.7-flash`가 Stage B에서 `llm_timeout`으로 탈락한 것과 같은 사유다.

## 판정 5. Lite 두 모델의 갈래가 재현됐다

- `gemini-3.1-flash-lite`는 PR #61에서 다시 코드를 짚었다. `use-auto-scroll.ts`,
  `interview-stream-view.tsx`, `@tanstack/react-virtual`을 인용하고 병목 지점을 물었다.

  물었다. **상한 3,500에서 2회 연속이다.** 상한 5,250에서는 주석을 그대로 인용했다.

첫 청크는 3.1-lite 1,037~1,119ms, 3.5-lite 1,196~1,398ms다. 세 회차를 합치면 둘 다 0.9~1.4초이고

커밋 메시지를 함께 본다.

# 근거 상한 5,250 전환과 Lite 두 모델 재측정 (2026-09-01)

## 상한을 코드에 반영했다

`EVIDENCE_SNAPSHOT_MAX_INPUT_TOKENS`를 3,500에서 **5,250**으로 올렸다.
`INTERVIEW_QUESTION_MAX_PROMPT_BYTES`는 유도식이라 12,107에서 **17,357**로 따라왔다
(5,250 × 3 + 시스템 1,349 + 2 + 허용 오차 256). 테스트 766개·`eslint`·`tsc --noEmit` 통과다.

### 3,500을 묶고 있던 근거를 왜 놓았나

3,500은 **Groq 무료 등급 분당 8,000토큰**에서 나온 값이다. 상한을 꽉 채운 요청이 입력 2,874~3,049에
응답 939~1,678토큰이라 최악 4,621토큰이 한도의 58%였고, 꼬리 질문이 매 턴 근거를 다시 싣기 때문에
남은 42%를 다음 턴 몫으로 남긴 것이다. 네 경로를 Gemini로 옮기면 그 벽이 없다.

**꼬리 질문은 이 값을 묶지 않는다.** 상한을 3,500에서 5,250으로 올릴 때 그 경로에서 늘어나는 것은
턴당 약 0.0004달러와 0초짜리 지연뿐이다. 실측 입력이 3,605에서 5,043토큰이고 `gemini-3.1-flash-lite`
단가 0.25달러/백만이면 턴당 0.00090달러에서 0.00126달러다. 첫 청크는 그 구간에서 0.9~1.6초로 평평하다.

**대신 배분 규칙으로 푼다.** 한도가 모델별로 걸린다는 것은 확인된 사실이다. Groq는 분당·하루 토큰이
모델별이고, 2026-08-25에 Stage A가 `gpt-oss-120b`의 하루 한도를 소진해 첫 질문을 `gpt-oss-20b`로
갈랐다. Gemini 무료 등급 할당량 이름도 `GenerateRequestsPerDayPerProjectPerModel-FreeTier`로 모델별이다.
**가장 자주 부르는 꼬리 질문을 앞 단계와 같은 모델에 두지 않는다**는 규칙이 상한이 아니라 이 문제의
해법이다. 유료 등급 한도가 모델별인지는 아직 확인하지 않았다.
