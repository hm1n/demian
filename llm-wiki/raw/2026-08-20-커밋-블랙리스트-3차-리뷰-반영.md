# 커밋 블랙리스트 3차 리뷰 반영 기록

## 참조

- `raw/2026-08-20-커밋-블랙리스트-2차-리뷰-반영.md`의 후속 기록입니다.
- PR #7 Codex 리뷰 `r3820297805`에서 단순 키워드가 기능 커밋을 유지보수 커밋으로 오분류하는 문제가 확인됐습니다.

## 결정

- 제목에 Conventional Commit 접두사가 있으면 타입과 스코프만 직접 지표로 사용합니다. 본문의 키워드는 판별하지 않습니다.
- 접두사가 없는 제목은 제목 전체가 유지보수 문장 형태와 일치할 때만 분류합니다.
- `Bump X from A to B` 제목은 작성자가 봇일 때만 의존성으로 분류합니다.
- 병합 판별과 카테고리 우선순위는 유지합니다.
- Conventional Commit의 `style:` 타입은 subject 전체가 포맷팅 문장일 때만 인정합니다. bare `style`과 `정렬` 키워드는 실데이터 검증 결정대로 복원하지 않았습니다.
- `fix(deps):`는 scope만으로 인정하지 않고 subject가 `update` 또는 `bump`로 시작할 때만 의존성으로 분류합니다. `chore|build|ci`는 타입 자체가 비기능 선언이므로 subject 검증을 요구하지 않습니다.
- 제외 로그와 텔레메트리, 후행 경계 규칙, 추가 실데이터 검증은 이번 범위에 포함하지 않았습니다.

## 트레이드오프

- Conventional Commit을 사용하지 않고 봇도 아닌 저장소에서는 유지보수 커밋이 상세 조회 대상으로 더 많이 넘어갈 수 있습니다. 이에 따라 2차 API 호출과 후보 노이즈가 늘어날 수 있습니다.
- 과다 제외는 경험 후보를 복구할 수 없지만 과소 제외는 상세 조회 비용이 늘어나는 문제이므로 정밀도를 우선했습니다.
- scope 없는 `chore:`는 안전한 방향으로 미분류 처리합니다.

## 검증

- 기능 제목의 Conventional Commit 형태와 접두사 없는 bare title 형태를 짝으로 회귀 테스트했습니다.
- 봇과 사람 작성자의 동일한 `Bump` 제목을 구분하는 테스트를 추가했습니다.
- 전체 테스트 97개, TypeScript 검사, ESLint 검사가 통과했습니다.
