# 네 경로 모델 선정 투표 개최 기록

## 문서 목적

네 경로(Stage A, Stage B, 첫 질문, 꼬리 질문·채팅)의 모델을 정하기 위해 관점이 서로 다른 서브에이전트
8개에게 각각 독립적으로 후보를 지목하게 한 절차를 기록한다. 이 문서는 절차와 지시문을 남기고, 실제 선택
결과는 결과 문서에 따로 남긴다. 결론 확정은 이 절차의 산출물이 아니다. 최다 득표와 차득표 두 모델을
비교 테스트하는 것이 다음 단계다.

## 설계 결정 네 가지

**1. 관점을 여덟으로 갈랐다.** 특히 품질을 둘로 나눴다. 이 프로젝트에서 Stage A가 실패한 방식은 판단이
틀린 것이 아니라 전수 응답 계약을 어긴 것이었고, 첫 질문이 실패한 방식은 형식이 아니라 없는 사실을 만든
것이었다. 두 실패는 원인과 해법이 다르므로 한 관점에 묶으면 결과가 뭉개진다.

**2. 경로별로 1순위와 2순위를 받는다.** 네 경로의 요구가 서로 다르므로 전체에서 모델 하나만 뽑으면 Stage
A의 표와 첫 질문의 표가 섞인다. 집계도 경로별로 한다.

**3. 각 에이전트는 투표라는 사실도, 다른 에이전트의 존재도 모른다.** 지시문에서 투표·집계·다른 관점이라는
말을 뺐다. 이 말이 남으면 에이전트가 자기 관점을 여덟 중 하나로 인식하고 "다른 관점이 반대할 수 있으니
균형을 맞추자"는 방향으로 결론을 흐린다. 관점은 편향이 아니라 그 에이전트에게 주어진 유일한 판정 기준으로
제시했다.

**4. 동표는 자동 규칙으로 깨지 않는다.** 두 후보를 그대로 올려 사람이 보고 결정한다. 그래서 지시문에
순위의 근거를 한 문장으로 남기도록 강제했다. 득표수만으로는 사람이 판단할 재료가 없다.

## 관점 8개

| 이름 | 판정 기준 | 순위를 정하는 값 | 판정에 넣지 않는 것 |
| --- | --- | --- | --- |
| `cost-first` | 세션 1회 총 단가 | 입력·출력·캐시 단가를 경로별 실제 토큰 수에 대입한 달러 | 품질, 지연, 구현 비용 |
| `quality-first` | 출력 내용의 사실성과 코드 이해력 | 없는 사실을 만들지 않는지, 인용이 입력 안에 있는지, diff에서 변경 의도를 읽어내는지 | 단가, 지연, 구현 비용 |
| `contract-first` | 형식 계약 준수 | 전수 응답 준수, `anyOf`(string 또는 null) 포함 스키마 수용, 스키마 검증 실패율, 질문 1개 규칙 | 단가, 문장 품질, 지연 |
| `latency-first` | 사용자가 기다리는 시간 | 배치는 총 지연 최댓값 27.5초, 스트리밍은 첫 청크 지연과 청크 개수 | 단가, 품질, 구현 비용 |
| `balanced` | 가중 합산 점수 | 비용 40퍼센트, 품질 35퍼센트, 지연 25퍼센트로 10점 만점 환산 | 없음 |
| `risk-first` | 6개월 뒤에도 같은 조건인가 | 인상 예정일, Preview 여부, deprecate 이력, 피크 요금제, 유료 등급 접근 가능성 | 현재 단가의 절대값, 품질 |
| `data-policy-first` | 교육생 코드를 보내도 되는가 | 학습 금지 조항의 등급 구분, 보관 기간, ZDR 제공, 조항 원문 확인 가능성 | 단가, 품질, 지연 |
| `impl-cost-first` | 우리가 새로 써야 할 코드량 | 제공자 증가 수, SDK 의존성 추가, 오류 분류 갈래 추가, 캐시·구조화 출력 문법 차이, 모델 문자열만으로 교체 가능한지 | 단가, 품질, 지연 |

## 여덟에게 똑같이 준 것

관점만 다르고 근거는 같아야 결과가 비교 가능해진다. 다음을 동일하게 전달했다.

| 항목 | 내용 |
| --- | --- |
| 서비스 설명 | 저장소의 커밋과 diff로 경험을 골라 주고 코드 근거로 면접 질문을 던진다. 대상은 부트캠프 교육생이고 그들의 코드가 프롬프트에 그대로 들어간다 |
| 네 경로 정의 | 호출 방식, 입출력 토큰 규모, 예산 상수, 각 경로의 최우선 규칙 |
| 읽을 자료 | `raw/2026-08-27-모델-단가-데이터조항-확인.md`, `output/2026-08-27-LLM-사용-기능-정리.md`, `wiki/2026-08-25-첫-질문-생성-provider-실측과-재개-방침.md`, `wiki/2026-08-27-Stage-A-전량투입-정렬-전환-검토.md`, `wiki/2026-08-26-Stage-A-B-Gemini-확정-고도화-설계.md` |
| 근거 강도 규칙 | 공식 문서 확인 > 우리 실측 > 전언. 전언을 쓸 때는 전언임을 밝힌다. 자료에 없는 벤치마크나 단가를 만들어 쓰지 않는다 |
| 판단 유보 금지 | 불확실해도 경로마다 모델을 하나씩 지목한다. 조건이 필요하면 결론과 별도로 적는다 |
| 출력 형식 | 경로 네 개에 각각 1순위·2순위·근거 한 문장, 그리고 탈락 목록과 조건 |

`impl-cost-first`에게만 자료를 더 줬다. 배선 상태는 문서로 판정할 수 없으므로 `package.json`,
`llm-provider.ts`, `stage-a.ts`, `stage-b.ts`, `question-generation.ts`를 직접 읽게 했다.
`contract-first`에게도 스키마 실물을 보게 하려고 `stage-a.ts`를 추가로 줬다.

## 집계 방식

**`data-policy-first`와 `risk-first`는 득표수로 더하지 않는다.** 이 둘은 선호가 아니라 탈락 조건이다. 데이터
조항을 통과하지 못하는 후보는 나머지 여섯 관점에서 만점을 받아도 쓸 수 없으므로, `data-policy-first`의
결과는 후보 명단을 먼저 걸러내는 필터로 쓴다. `risk-first`의 결과는 최종 두 후보에 붙이는 경고로 쓴다.

나머지 여섯 관점의 1순위를 경로별로 세어 최다 득표와 차득표를 뽑는다. 동표면 두 후보를 그대로 올린다.

## 다음 단계

최다 득표와 차득표 두 모델을 경로마다 실제로 호출해 비교한다. 비교 항목은 경로 성격에 따라 갈린다. Stage
A는 66묶음 전수 응답 준수율 3회, Stage B는 총 지연 최댓값과 인용 검증 통과 여부, 첫 질문은 만들어낸 사실
건수와 첫 청크 지연이다. 비교 전 선행 조건은 `raw/2026-08-27-모델-단가-데이터조항-확인.md`의 확인 필요
항목 중 유료 등급 한도와 구조화 출력 지원 두 개다.
