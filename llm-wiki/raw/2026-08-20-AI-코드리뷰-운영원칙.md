# AI 코드 리뷰 운영 원칙

출처는 프로젝트 owner가 2026-08-20에 직접 제시한 원칙 원문이다. 아래 본문은 가공하지 않고 그대로 옮긴 것이다.

---

AI 코드 리뷰의 목적은 모든 잠재적 문제를 제거하는 것이 아니라, 현재 PR을 안전하게 머지할 수 있는지 판단하는 것입니다.

리뷰 우선순위

* P0 / P1
    * 현재 PR의 merge blocker로 취급합니다.
    * 즉시 수정 후 재검증합니다.
    * 기능 오동작, 데이터 손실, 보안 문제, 핵심 요구사항 위반 등 실제 사용자 영향이 큰 문제를 포함합니다.
* P2 / P3
    * 기본적으로 현재 PR의 merge blocker로 취급하지 않습니다.
    * 후속 Issue 또는 backlog로 분리합니다.
    * robustness 개선, 희귀한 edge case, 극단적인 race condition, 구조 개선 등이 해당합니다.
    * 단, 현재 PR의 Acceptance Criteria를 직접 위반하거나 수정 비용이 매우 작은 경우에는 함께 반영할 수 있습니다.

리뷰 종료 기준

리뷰어가 더 이상 지적하지 않을 때까지 반복하지 않습니다.

다음 조건을 만족하면 머지할 수 있습니다.

* Acceptance Criteria를 모두 만족합니다.
* P0 / P1 문제가 해결되었습니다.
* 테스트, lint, typecheck 등 필수 검증이 통과했습니다.
* 남아 있는 P2 / P3 문제는 후속 작업으로 분리되었습니다.

재리뷰 원칙

기본 리뷰 흐름은 다음과 같습니다.

1차 리뷰 → P0/P1 수정 → 재리뷰 → Merge

* 재리뷰는 수정된 P0/P1이 정상적으로 해결되었는지 확인하는 용도로 사용합니다.
* 재리뷰에서 새롭게 발견된 P2/P3 문제 때문에 리뷰를 반복하지 않습니다.
* 새롭게 발견된 non-blocking 문제는 별도 Issue 또는 backlog로 이동합니다.

리뷰 Agent의 판단 기준

리뷰 Agent는 다음 항목을 우선적으로 찾습니다.

* Acceptance Criteria 위반
* 명백한 correctness bug
* 데이터 손실 또는 데이터 누락 가능성
* 보안 및 권한 문제
* 기존 핵심 기능의 regression
* 예외 처리로 인해 사용자에게 잘못된 결과가 전달되는 문제

다음 항목은 특별한 이유가 없다면 blocking issue로 취급하지 않습니다.

* 발생 가능성이 매우 낮은 극단적 edge case
* 미래 확장성을 위한 구조 개선
* 현재 요구사항에 포함되지 않은 robustness 개선
* 코드 스타일 또는 선호의 차이
* PR 범위 밖의 리팩터링
* 현재 기능 동작에 직접 영향을 주지 않는 개선 제안

핵심 원칙

AI 리뷰는 완벽한 코드를 만들기 위한 무한 탐색 과정이 아닙니다.
현재 PR의 요구사항과 위험도를 기준으로 merge 가능 여부를 판단하고, 중요하지 않은 문제는 후속 작업으로 분리합니다.

리뷰에서 발견된 모든 문제를 즉시 해결하려고 하지 말고, severity와 현재 PR의 scope를 기준으로 반영 여부를 판단합니다.
