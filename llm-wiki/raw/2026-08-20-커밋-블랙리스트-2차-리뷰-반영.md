# 커밋 블랙리스트 2차 리뷰 반영 기록

## 참조

- `raw/2026-08-20-커밋-블랙리스트-필터-구현.md`의 구현 결정을 보완합니다.
- `raw/2026-08-20-커밋-블랙리스트-실데이터-검증.md`의 오분류 검증을 확장합니다.
- GitHub Issue #2 2차 코드 리뷰의 C1부터 C6까지 반영했습니다.

## 변경 내용

- 한국어 키워드 앞에 한글이 오는 부분 문자열은 블랙리스트로 분류하지 않도록 경계를 추가했습니다. `문서화`처럼 키워드로 시작하는 제목은 계속 분류합니다.
- 커밋 본문에 포함된 하위 커밋 목록이 기능 커밋을 제외하지 않도록 제목만 분류 대상으로 사용합니다.
- 제목만 사용하는 결정에 따라 `CommitSummary.message`를 제거했습니다.
- 커밋 페이지의 JSON 파싱과 요약 매핑을 같은 실패 경계에 두었습니다. 첫 페이지의 잘못된 응답 형태는 `network`, 일부 페이지를 수집한 뒤의 실패는 기존 결과를 포함한 `partial_failure`로 변환합니다.
- 런타임 소비처가 없는 블랙리스트 카테고리 배열을 제거하고 유니온 타입을 직접 선언했습니다.
- 기능 변경을 의존성 변경으로 오분류하는 `upgrade` 키워드를 제거했습니다.

## 회귀 검증

- 주문서, 설문서, 스프린트, 프린트처럼 한국어 키워드를 부분 문자열로 포함하는 기능 제목이 제외되지 않는지 검증했습니다.
- 본문에만 `docs`나 `typo`가 있는 기능 커밋이 상세 조회 대상으로 남는지 검증했습니다.
- `upgrade`를 포함한 기능 및 리팩터링 제목이 제외되지 않는지 검증했습니다.
- 첫 페이지와 후속 페이지에서 커밋 응답 형태가 잘못된 경우 타입이 있는 오류와 이미 수집한 커밋이 보존되는지 각각 검증했습니다.
- 전체 테스트, TypeScript 검사, ESLint 검사를 실행했습니다.

## 확인 필요

- 블랙리스트 키워드는 다른 실제 Repository 데이터에서도 계속 검증해야 합니다.
- 후행 경계는 적용하지 않았습니다. 선행 경계만 막았으므로 `문서함`, `오타쿠`, `포맷터`처럼 키워드로 시작하는 합성어는 계속 분류됩니다. `문서화`처럼 정상적으로 분류해야 하는 제목과 순수한 경계 규칙만으로 구분할 수 없어 의도적으로 남겼으며, 실데이터에서 오분류가 관찰되면 키워드별로 판단해야 합니다.
- `upgrade`를 제거해 `chore: upgrade react to 19` 같은 의존성 커밋도 상세 조회 대상으로 남습니다. 기능 변경 오분류를 줄이는 정밀도를 높이는 대신 의존성 커밋을 찾아내는 재현율을 일부 포기한 결과입니다.

## 재현 수단

- 실데이터 검증을 재현할 수 있도록 `scripts/manual-test-commits.ts`를 저장소에 추가했습니다. 저장소 밖에 있던 수동 검증 절차를 코드와 함께 보존하기 위한 결정입니다. `--blacklist`를 붙이면 카테고리별 건수와 제외된 제목을 표준 출력으로 확인할 수 있습니다.
