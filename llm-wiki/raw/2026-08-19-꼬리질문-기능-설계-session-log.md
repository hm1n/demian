# 꼬리 질문 기능 설계 세션 로그

## 문서 목적

"꼬리 질문" 기능을 설계하면서 논의하고 결정한 내용을 보존한다. "사용자 답변" 항목도 별도 기능으로 두지 않고 이 문서에서 함께 다루기로 했다.

## 논의 내용

### "사용자 답변"을 별도 기능으로 두지 않기로 한 이유

MVP 목록에는 "사용자 답변"이 독립된 항목으로 있었다. 논의 결과 사용자 답변은 그 자체로 화면이나 별도 로직을 갖는 기능이 아니라, 꼬리 질문을 만들기 위한 입력이라고 판단했다. 그래서 "사용자 답변" 항목을 따로 문서화하지 않고 "꼬리 질문" 기능 문서 안에서 답변 처리 방식까지 함께 정의하기로 했다.

### 답변 저장 시점

사용자가 답변을 제출하면 바로 저장하는 안과, 다음 꼬리 질문이 만들어진 뒤에 함께 확정 저장하는 안을 비교했다. 제출 즉시 저장하는 것으로 결정했다. 꼬리 질문 생성이 실패하더라도 사용자가 이미 작성한 답변은 유실되지 않아야 하기 때문이다.

### 꼬리 질문 생성 근거 범위

꼬리 질문을 만들 때 원래 질문의 근거 커밋만 쓸지, 사용자 답변 내용까지 반영할지, 나아가 지금까지의 대화 전체 이력을 반영할지 논의했다. 처음에는 원래 근거 커밋과 직전 답변만 반영하는 안을 검토했다. 이후 근거 출처가 나중에 Repository 외의 보조 맥락으로 확장될 가능성을 고려해 다시 검토했다. 대화가 여러 턴 이어지는 구조에서 직전 답변만 반영하면 이전 답변 내용을 놓치고 같은 질문을 반복할 위험이 있고, 대화 전체 이력을 반영하는 방식이 나중에 보조 맥락이 추가되어도 같은 방식으로 자연스럽게 확장된다는 점에서 대화 전체 이력과 원래 근거 커밋을 모두 반영하는 것으로 결정했다. 인터뷰 특성상 대화 턴 수가 많지 않아 지금 시점에 비용을 이유로 이력을 줄일 필요는 없다고 판단했다.

### 종료 조건

꼬리 질문을 언제까지 계속 만들지 논의했다. 사용자가 직접 인터뷰 종료를 선택하는 것으로 결정했다. AI가 답변 품질이나 내용을 보고 자동으로 종료 시점을 판단하는 안은 MVP 단계에서 판단 기준을 정하기 어려워 채택하지 않았다.

## 결정 사항 요약

- "사용자 답변"은 별도 기능이 아니라 이 기능의 입력으로 다룬다.
- 사용자가 답변을 제출하면 즉시 저장한다. 꼬리 질문 생성 성공 여부와 관계없이 답변은 유실되지 않는다.
- 꼬리 질문을 만들 때는 대화 전체 이력과 원래 근거 커밋을 모두 반영한다.
- 인터뷰 종료는 사용자가 직접 선택한다. AI가 자동으로 종료를 판단하지 않는다.
- 질문 생성 내용까지만 이 기능이 담당하고, 화면 출력 방식은 "실시간 AI Streaming 응답" 기능이 담당한다.

## 확인 필요

- 대화 이력이 길어질 때 프롬프트에 포함할 이력의 구체적인 형식과 요약 방식
- 인터뷰 종료 시점에 정리되지 않은 답변이 있을 때의 처리 방식
- 종료한 인터뷰를 사용자가 다시 이어갈 수 있는지 여부
