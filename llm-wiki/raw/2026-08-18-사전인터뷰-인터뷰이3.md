# 사전 인터뷰 - 인터뷰이 3

## 인터뷰 목적

개발 교육생이 프로젝트 경험을 정리하거나 면접을 준비할 때, 자신이 해결한 문제와 기술적 판단을 발견하고 설명하는 데 실제로 어려움을 겪는지 확인한다. 인터뷰에서는 먼저 제품 아이디어를 설명하지 않고, 응답자가 스스로 겪었던 경험과 어려움을 말하도록 유도한다.

## 인터뷰 내용

1. 최근 프로젝트를 이력서나 포트폴리오에 정리해본 적이 있나요? 있었다면 어떤 과정이 가장 어려웠나요?
없다. 지금은 지금까지 했던 이력서를 바꾸고 있다. 내가 어떤 생각으로 이걸 했었지? 를 ADR 형태로 작성하고 있는데, 코드의 Before를 찾고 After가 어떻게 바뀌었는지 파악하고 정리하는 게 어렵다.

2. 지금 최근 프로젝트에서 본인이 해결했던 기술적인 문제 하나를 떠올려서 설명해주실 수 있나요?
소셜 로그인 구현. 데이터를 받아서 서비스로 돌아 오는데 거기서 어떤 오류가 나서 폼이 떠야 하는데 폼이 안 뜨는 문제 발생. 해결은 했는데 해결 과정이 아직 머리 속에서 정리가 잘 되지 않는다.

3. 프로젝트 경험을 정리하거나 다시 떠올릴 때 주로 무엇을 참고하나요? 예: 기억, GitHub, PR, Notion, 팀원 등
그 때 작성했던 노션이나, 팀원들한테 보냈던 메시지, 깃허브 저장소 코드, PR 이력 등을 본다. 노션에는 AI 활용해서 작업한 내용과 어떤 상황이었는지, 해결 방안, 무엇 때문에 그랬던 건지를 노션에 정리하고 있다.

4. 예전에 작성한 코드를 다시 봤을 때 "왜 이렇게 구현했지?" 또는 당시의 선택 이유가 잘 기억나지 않았던 경험이 있나요?
있다. 하나하나가 잘 생각이 안 난다. 문서화를 잘 안 해서 그런 것 같다.

5. 프로젝트를 이력서나 포트폴리오에 작성할 때 어떤 경험을 강조해야 할지 판단하기 어려웠던 적이 있나요? 있었다면 어떤 점이 어려웠나요?
있었는데 지금은 좀 어떤 걸 어필해야겠다는 기준은 조금 생긴 것 같다. 수치를 강조해야 한다는 걸 배우다 보니 어떻게든 수치를 강조할 수 있는 비포 애프터를 찾아야겠다는 알게 되었다. 그걸 적용해야겠다는 건 다른 문제긴 하지만 어쨌든 뭘 강조해야 하는지는 알겠다.

6. 면접에서 본인의 프로젝트나 코드에 대해 질문받는다면 어떤 부분을 설명하는 것이 가장 어렵거나 걱정되나요?
상황을 잘 정리해서 조리있게 말할 수 있는지를 잘 모르겠다. 처음부터 말하면 너무 장황하게 설명하게 되는데, 면접에서 핵심만 잘 설명할 수 있을지 모르겠다.

7. 내 GitHub Repository를 분석해서 내가 놓치고 있던 개발 경험을 찾아주고, 실제 코드를 기반으로 질문을 던져 그 경험을 설명하는 연습까지 할 수 있다면 사용해보고 싶으신가요?
당연히 쓴다.

8. 사용 의향: 있음 / 애매함 / 없음
있다.

9. 실제 Repository를 연결해서 테스트해볼 의향: 있음 / 없음
있다.
