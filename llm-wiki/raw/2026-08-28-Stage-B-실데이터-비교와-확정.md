# Stage B 실데이터 비교와 모델 확정

## 확정

**Stage B는 `gemini-3.5-flash-lite`로 확정한다. 2순위는 `gemini-3.1-flash-lite`다.**

Stage A와 다른 모델을 쓴다. 두 단계의 모델 주입 지점이 `llm-provider.ts`에서 이미 분리되어 있어 배선
비용은 상수 문자열 하나다.

**현재 프로덕션 모델 `gemini-3.7-flash`는 예산 초과로 실패하므로 교체가 필수다.**

## 측정 방법

- 프로덕션 계측 스크립트의 `stage-b` 단계다. `--stage-b-model`로 모델만 갈아탔고 제공자 경로는
  `createStageBModel`의 네이티브 Google 경로 그대로다. 로컬 전환 스위치를 쓰지 않았으므로 **프롬프트가
  프로덕션과 완전히 같다.**
- 입력은 본인 저장소 `hm1n/demian`이고 상세 조회를 캐시해 모든 실행이 같은 입력을 받았다.
- 후보 묶음 12개를 펼친 커밋 30건, PR 12개, patch는 후보당 2,000자씩 30개 전원 배정됐다. 굶은 후보는 0이다.
- Stage B 직렬화는 162,541바이트(158.7KB)이고 patch 총량 상한 60,000자를 모두 썼다.
- 로그에는 수치와 선정 결과만 남겼다.

## 판정 1. 현재 프로덕션 모델은 쓸 수 없다

`gemini-3.7-flash`가 `STAGE_B_TOTAL_BUDGET_MS` 55초를 넘겨 `llm_timeout`으로 끝났다. 합성 246토큰 입력에서
60초 무응답이었던 것과 일치한다. **지금 배포된 상태로는 Stage B가 실데이터에서 완주하지 못한다.** 이슈 #66
시점의 관측이 아니라 오늘 실측이다.

## 판정 2. 인용 근거의 풍부함이 갈린다

Stage B의 품질은 지연이 아니라 **얼마나 많은 근거를 실제 입력에서 끌어오는지**다. 이 경로는 인용 SHA와 파일
경로가 입력 안에 있는지 검증하므로, 인용이 많다는 것은 검증을 통과한 근거가 많다는 뜻이다.

- `gemini-3.1-flash-lite`는 후보마다 관련 커밋 1개, 인용 파일 2개로 **가장 얇다.** 세 후보가 모두 같은 값이라
  최소한만 채운 것으로 보인다.
- `gemini-3.5-flash-lite`는 인용 파일 5~9개, 관련 커밋 1~3개로 **후보마다 다르게 채웠다.** 같은 patch 예산에서
  더 많은 근거를 찾아냈다.
- `gemini-3.6-flash`는 근거 문장이 216~301자로 가장 길고 관련 커밋을 2~4개로 묶었다. 다만 인용 파일은
  3.5-lite보다 적다.

세 모델 모두 인용 검증을 통과했다. 입력 밖 SHA나 경로를 만든 사례는 없다.

## 판정 3. `gemini-3.5-flash-lite`가 지연과 근거를 함께 만족한다

4.2초로 예산의 7.6%만 쓰면서 인용 파일을 가장 많이 끌어왔다. `gemini-3.6-flash`가 근거 문장은 더 길지만
32.9초로 예산의 60%를 쓴다. Stage B 라우트는 상세 조회까지 같은 예산 안에서 처리하므로 남는 22초로 커밋
30건을 조회해야 한다. **여유가 없다.**

`gemini-3.1-flash-lite`는 가장 빠르지만 근거가 가장 얇다. Stage A는 diff를 읽지 않고 지시 준수만 요구하므로
이 모델이 맞지만, Stage B는 diff를 읽어 근거를 뽑는 경로라 얇은 인용이 곧 화면에 표시될 근거의 부족으로
이어진다.

## 확정 근거 정리

| 축 | 판정 |
| --- | --- |
| 예산 준수 | 3.5-lite 7.6%, 3.1-lite 5.8%, 3.6-flash 59.8%, 3.7-flash 초과 |
| 인용 근거 | 3.5-lite가 파일 5~9개로 최다. 3.1-lite는 2개로 최소 |
| 근거 문장 길이 | 3.6-flash가 216~301자로 최장이나 예산을 60% 쓴다 |
| 인용 검증 | 세 모델 모두 통과. 입력 밖 SHA·경로 0건 |
| 단가 | 3.1-lite 0.25/1.50 < 3.5-lite 0.30/2.50 < 3.6-flash 0.75/3.75 |
| 인상 예정 | Lite 두 모델 없음. 3.6·3.7 2027-01-01 두 배 |
| Stage B 회당(40,000/3,000) | 3.1-lite 0.01450달러, 3.5-lite 0.01950달러, 3.6-flash 0.04125달러 |

3.5-lite가 3.1-lite보다 회당 0.005달러 비싸다. 분석 1,000회에 5달러 차이다. **그 값을 인용 근거의 두세 배
차이와 맞바꾸는 것이 이 확정의 내용이다.**

## 이 확정이 남긴 조건

1. **판단 품질을 사람이 확인해야 한다.** 인용 개수는 근거의 양이고 질이 아니다. 3.5-lite가 뽑은 근거 문장이
   실제로 쓸 만한지, 3.6-flash의 긴 문장이 더 나은지는 사람이 읽어야 갈린다. 인용 개수만으로 확정한 것은
   지금 시점의 최선이다.
2. **기여 항목 없이 쟀다.** 사용자가 입력한 기여 항목이 있으면 선택이 달라질 수 있다.
3. **각 모델을 1회만 실행했다.** Stage A에서는 Lite 계열의 반복 분산이 작았으나 Stage B에서 같은지는
   확인하지 않았다.
4. **patch 예산 상수를 재산정할 여지가 생겼다.** 3.5-lite가 예산의 7.6%만 쓰므로 patch 총량 60,000자를 늘려
   더 많은 근거를 실을 여유가 있다. `wiki/2026-08-26-Stage-A-B-Gemini-확정-고도화-설계.md`가 별도 이슈로
   미룬 항목이다.
5. **유료 등급 전환이 선행 조건이다.** Stage A와 같다.
