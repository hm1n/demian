# Issue 제목 규칙

Issue 제목은 `[{라벨-슬러그}/{도메인}] 이슈명` 형식을 사용합니다. `{도메인}`을 생략하면 `[{라벨-슬러그}] 이슈명` 형식을 사용합니다.

## 라벨 슬러그

제목에는 GitHub Label 이름 자체가 아니라 Label에서 파생한 슬러그를 사용합니다.

- 이모지를 제거합니다.
- 모든 영문자를 소문자로 바꿉니다.
- 공백은 제거하거나 단어 경계를 보존해야 할 때 하이픈으로 바꿉니다.
- 기호가 단어를 구분하면 하이픈으로 바꿉니다.

| GitHub Label | 제목 슬러그 | 근거 |
| --- | --- | --- |
| `⚙ Setting` | `setting` | 변환 규칙으로 유도, 이력 전례 없음 |
| `✨ Feature` | `feature` | 기존 이슈 이력에서 확인 |
| `🌏 Deploy` | `deploy` | 변환 규칙으로 유도, 이력 전례 없음 |
| `🎨 HTML&CSS` | `html-css` | `&`가 두 단어의 경계이므로 하이픈으로 변환, 이력 전례 없음 |
| `🐞 BugFix` | `bugfix` | 기존 이슈 이력에서 확인 |
| `📃 Docs` | `docs` | 기존 이슈 이력에서 확인 |
| `🔨 Refactor` | `refactor` | 변환 규칙으로 유도, 이력 전례 없음 |
| `🙋‍♂️ Question` | `question` | 변환 규칙으로 유도, 이력 전례 없음 |

새 Label이 추가되면 이모지를 제거하고 영문을 소문자로 바꾼 뒤, 공백이나 단어 구분 기호를 하이픈으로 바꾸어 슬러그를 유도합니다.

## 도메인

- `{도메인}`은 작업 대상 기능이나 영역을 나타내는 소문자 kebab-case 영문 키워드입니다. 예: `github-repo`, `llm-wiki`.
- 기존 이력에서는 Repository 조회나 `llm-wiki`처럼 제목의 범위를 더 좁히는 영역이 있을 때 도메인을 사용합니다.
- 라벨과 이슈명만으로 범위가 드러나 별도 영역을 적지 않은 기존 이슈는 도메인을 생략합니다.

## 예시

아래 제목은 이 Repository에 실제로 존재합니다.

```text
[feature] 경험 후보 생성
[docs] 커밋 메시지 명사형 종결 규칙 명문화
[bugfix] Wave 0 머지 후 기여 항목 테스트 실패 정정
```

### 잘못된 제목과 올바른 제목

| 실패 유형 | 잘못된 제목 | 올바른 제목 |
| --- | --- | --- |
| 실제 발생 사례 | `[📃 Docs/llm-wiki] Wave 0 문서 감사 기록 누락 보완` | `[docs/llm-wiki] Wave 0 문서 감사 기록 누락 보완` |
| 이모지 포함 | `[✨ feature] 경험 후보 생성` | `[feature] 경험 후보 생성` |
| 대문자 시작 | `[Docs] 커밋 메시지 명사형 종결 규칙 명문화` | `[docs] 커밋 메시지 명사형 종결 규칙 명문화` |
| Label 이름의 공백 유지 | `[📃 Docs /llm-wiki] Wave 0 문서 감사 기록 누락 보완` | `[docs/llm-wiki] Wave 0 문서 감사 기록 누락 보완` |

`이슈명`은 작업 내용을 이해하기 쉬운 한국어로 작성합니다.
